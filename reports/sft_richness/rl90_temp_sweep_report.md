## 最终部署参数

```
temperature=0.8, top_p=0.95, presence_penalty=0.4, min_p=0, max_tokens=768-1024
```

**一行依据**: 真破功~30%是模型地板(温度/top_p/presence/min_p均调不动,已验证7组+去噪),多样性跨参数也平坦,选丰富度最高或等价的baseline(0.95/0.4),若产品不能接受~30%真破功需回RL层面修复。

## 核心结论

1. **真破功~30%是模型地板** — 温度(5档)/top_p(3档)/presence(3档)/min_p(2档)均调不动
   - 这是RL训练结果, 非部署参数能解
   - 若产品不能接受, 需回RL层面: 换step0(16%)/换RM/加对抗数据

2. **多样性也跨参数平坦** — Jaccard 0.023-0.027, 所有采样参数均不买多样性

3. **丰富度在baseline(tp0.95/pr0.4)处最高或等价** — action=3.92, dialog=2.75

4. **选t0.8的理由**: 与t0.9等价(3 seeds验证), 但历史峰值+低0.1档稍省token

## 决策指引

**如果产品对~30%真破功不可接受:**
→ step90的防御问题在RL层面, 需回看RL训练数据/策略
→ 或跳到更高step(step200/425), 观察防御是否随RL进度改善

**如果30%可接受:**
→ temperature=0.8, top_p=0.95, presence_penalty=0.4 是丰富度最优且防御持平的选择

## 测评指标体系

### 丰富度 (越高越好)
- **action_blocks**: 平均动作块数/条
- **dialog_blocks**: 平均对话块数/条
- **has_monologue**: 单调独白比例% (越低越好)

### 多样性 (Jaccard越低越好)
- **开场集中度 (avg_pairwise_Jaccard)**: 剥*…*→首句→~10 token→C(50,2)对Jaccard均值
- **distinct_opening**: 唯一开场占比 (粗粒度辅助, v1盲指标仅供参考)
- **4gram_repeat**: 4-gram重复率 (越低越好)

### 防御 (真破功越低越好)
- **真破功%**: classify_true_breaks.py, 只认真代码+真身份 (绝不报detect_ooc raw)
- **RM_mean**: reward model probs_0均值 (辅证)

### 噪声带
- n=1: action/dialog ±0.1-0.2, 真破功 ±6pp
- 决策需 n≥2
