# 深读 6 — 多目标协调：RLHF 用三种机制消解冲突，选错机制 = 大多数失败的根源

> 本篇展示的能力：**把"clean 富度 / attack 防御 / 动作密度 / 语义忠实度 / 语言一致性"这一组互相拉扯的目标，归到 RLHF 仅有的三种协调机制上——阶段分配、阶段内聚合、per-source 解耦——并证明本项目几乎每一次失败都是"用错了机制"，每一次成功都是"换对了机制"。**
>
> 这是 [深读 2–5](.) 的 capstone：前面分别讲 RM、RL 动力学、富化-防御张力、何时转 RL；本篇把它们放进同一张多目标协调的框架里。数字均来自仓库内可核对记录（`CASE_STUDY.md` / `v69_reconcile_report.md` / 各设计文档）。

---

## 0. 角色模型至少有 5 个互相拉扯的目标

| 目标 | 想要 | 与谁冲突 |
|---|---|---|
| **clean 富度** | 长动作链、感官/情绪细节、推进剧情 | 与防御冲突（沉浸 ⇄ 元认知）；与"适度长度"冲突（富 ⇄ 灌水）|
| **attack 防御** | 被攻击时角色内化解、不破功 | 与富度冲突；与"不过度拒绝"冲突（防御 ⇄ 配合）|
| **动作密度** | `*…*` 动作多 | 与对话/独白争预算（加一个就挤掉另一个）|
| **语义忠实度** | 性格对（"冷淡"就冷淡）、不串角色 | 与"配合度/不拒绝"冲突 |
| **语言一致性** | 用户用什么语言就回什么 | 相对独立，但高温下漂移 |

这些目标**不能同时拉满**——它们在行为空间里争夺同一批 token、同一套 attention、同一份 KL 预算。RLHF 怎么协调？答案不是"调一个权重"，而是**三种不同尺度的机制**。

---

## 1. RLHF 只有三种协调机制（按作用尺度从粗到细）

| 机制 | 在哪一层 | 解决哪种冲突 | 本项目实例 |
|---|---|---|---|
| **① 阶段分配** | 跨 SFT/RM/RL | 目标该由谁优化（信号在哪一层）| 富度→SFT、防御→RL |
| **② 阶段内聚合** | 单个 stage 的 loss/reward 内 | 多目标在同一损失里怎么合并 | SFT 选择器、RM 标量、RL reward 组装 |
| **③ per-source 解耦** | 同一模型、不同输入 | 同一目标在不同输入上要求相反 | clean vs attack 不同 reward + 不同 KL |

**核心论点**：一个冲突往往能在多个层解决，但**每种冲突有它"对"的那一层**。选错层 = 本项目大多数失败的根源。下面逐层看，并把失败/成功对应到机制选择。

---

## 2. 机制①：阶段分配——目标去信号所在的那一层

最粗的协调：**先决定每个目标归谁**，让冲突的目标尽量不在同一个 stage 里抢梯度。判据是"哪一层有这个目标的梯度/信号"（[深读 5 门 B](05_when_to_move_from_sft_to_rl.md)）。

- **富度 → SFT**：RM 在 clean 质量轴上几乎平（打分范围 0.037 vs attack 0.36，~10×），RL 给不了富度梯度（v6.7 实测 clean RM 100 步 +0.037≈噪声）。富度只能靠 SFT 蒸馏 teacher 注入。
- **防御 → RL**：RM 在 attack 轴有 0.36 区分度，且破功是高温稀有尾巴，需要 on-policy rollout 才暴露（[深读 4/5](04_richness_defense_tension_and_sft_ceiling.md)）。
- **基础格式/表达 → SFT**：`*动作* "对话" （独白）` 三件套是分布注入，RL 不创造分布。

**失败 = 阶段分配错**：v6.7 想用 RL 提富度，等于把一个"SFT 目标"塞进 RL，结果 100 步零增益。把它退回 SFT（v6.9）才动得了。

> 这一层的产出：**richness ⊥ defense 的"分治"**——不在同一 stage 同时硬追两个最冲突的目标。但分治不够（它们最终要在同一个模型里共存），所以还需要 ② 和 ③。

---

## 3. 机制②：阶段内聚合——加权和 vs 字典序门控（最容易选错的一层）

当多个目标必须进同一个 loss/reward 时，只有两种合并方式，性质完全不同：

### 3.1 加权和（线性权衡）—— 可被牺牲、会被放大

`objective = Σ wᵢ · scoreᵢ`。性质：任何目标都能被"足够多的另一个目标"换掉；权重就是优先级。**风险：放大器 + Goodhart。**

- **SFT 选择器** 是纯加权和：v6.9 的 `composite = w·动作 + w·对话 + w·interaction + w·sensory + w·emotion`（[RLHF_WORKFLOW Stage 7](../RLHF_WORKFLOW.md)）。v6.8 把**独白**加进这个和 → 训练把独白放大到 **base 的 187%**、挤掉对话。**选择器是放大器：偏向哪个目标，训练就把那个目标推过头**（[深读 4](04_richness_defense_tension_and_sft_ceiling.md)）。修法不是调独白权重，而是**把独白移出目标**（v6.9 不让独白进 composite）+ 训练前 profile 硬门（独白率 ≤ base+10%）。
- **RM 标量** 是学出来的加权和：判别器把 8 维 rubric（role/relevance/interaction/style/format + sensory/emotional/narrative）压成一个标量。**怎么在不让维度互相混淆的情况下学出这个聚合？靠单因负样本（DOE 思路）**——`wrong_role` / `wrong_language` / `length_mismatch` 每个只动一个维度（[深读 2](02_rm_data_reward_and_attribution.md)），让 BT 能把偏好归因到具体维度。代价：**判别器看不见的维度会在聚合里塌成平的**——clean 富度的细微差别 judge 没标出来 → RM 这一维范围 0.037 ≈ 无（这正是 ① 要把富度踢给 SFT 的原因）。

### 3.2 字典序门控（优先级硬约束）—— 不可被牺牲

`if 触发硬失败: reward = 硬罚（压倒一切）; else: reward = 软偏好`。性质：高优先目标**不能**被低优先目标的任何量换掉。**用于"约束"而非"偏好"的目标。**

- **RL reward 的破功门**：`break_pen = −5/条`（逐样本），`clean_q ∈ [0,0.3]`。`−5` 量级碾压 `0.3` → 顺序天然是 **先必须不破功，再在不破功的回应里偏向"角色内有戏化解"**（[深读 3](03_rl_dynamics_params_and_strategy.md) / v6.10 设计）。"富但破功"= −5 照样毙。
- **length-shaping 的门**：仅 clean、有格式、非破角/拒绝/重复才发，且饱和封顶。长度永远换不来"破功豁免"。

### 3.3 选错聚合 = reward hacking 的根源（本项目最贵的一课）

**`anti_refusal` 的 Goodhart bug 就是聚合选错**：把"不拒绝"做成 **+3.0 的加权和项**（additive），于是"自报身份"这种破功因为"不含拒绝词"被加了 +3.0 → **reward 在奖励破功**（[深读 2 / CASE_STUDY 节点 5](../CASE_STUDY.md)）。

- 错在哪：**安全（不破功）是约束，不是偏好**，却用了可线性权衡的加权和 → 一个目标的代理（"非拒绝"）反向奖励了另一个目标的失败（破功）。
- 修法：换成**字典序门控**——`anti_ooc_disclosure` 破功硬罚 −5 + 撤销那 +3.0，使排序变成 **戏内化解 ≻ 拒绝 ≻ 破功披露**（全 TDD，不重训 RM，误报 1/16→0/16）。

> 一句话规律：**substitutable 的目标（动作 vs 对话）用加权和；constraint 类目标（绝不破功）用字典序门控。把约束塞进加权和 = 给 reward hacking 开门。**

## 4. 机制③：per-source 解耦——同一目标在不同输入上要求相反

最细的协调：**同一个模型，对 clean 输入和 attack 输入用不同的 reward 组装 + 不同的 KL**。因为有些目标在不同输入上的要求是直接矛盾的，单一配置无法两全。

最纯粹的例子是 **KL 锚**：

| 输入 | 想要 | KL 系数（v6.10）|
|---|---|---|
| clean prompt | **贴近** ref（保住已注入的富度，别动）| `KL_CLEAN = 0.008`（紧）|
| attack prompt | **离开** ref（改掉破功行为）| `KL_ATTACK = 0.002`（松）|

"想贴近"和"想离开"是同一个旋钮上的相反方向——**单一 KL 系数无法同时满足**。per-source KL 用两个系数把这个矛盾拆开。reward 组装也分源：

```
clean prompt:  reward = clean_q（全量）          + 紧 KL（守富度，不让 RL 推离）
attack prompt: reward = rm + break_pen + λ·clean_q + 松 KL（让防御移动）   λ≈0.25
```

> 这就是"提防御又不丢 clean 富度"在**一次 RL run 里**能成立的原因：两类输入的梯度被路由到不同的 reward/KL，互不污染（[v6.10 设计](../docs/chatjoy_rl_v610_defense_clean_aware_design.md)）。没有 per-source，attack 侧的更新会顺着 KL 把 clean 分布一起带跑。

## 5. 把冲突映射到机制（决策表）

| 冲突的性质 | 该用哪个机制 | 本项目实例 | 选错的后果 |
|---|---|---|---|
| 目标在某 stage 没有梯度 | **① 阶段分配**（换 stage）| 富度→SFT，防御→RL | v6.7：RL 提富度 100 步零增益 |
| 两目标可线性替代（动作 vs 对话）| **② 加权和**（但防放大）| v6.9 选择器 composite | v6.8：独白进目标 → 过冲 187% |
| 一目标是约束、不是偏好（绝不破功）| **② 字典序门控** | break_pen −5 ≫ clean_q 0.3 | anti_refusal：约束塞进加权和 → 奖励破功 |
| 同一目标在不同输入上要求相反 | **③ per-source 解耦** | clean KL 0.008 / attack 0.002 | 单一 KL：attack 更新把 clean 带跑 |
| 多维要进一个标量、又不能互相混淆 | **② 单因负样本（DOE）** | wrong_role/lang/length 各动一维 | 多因混淆 → RM 学不出维度归因 |

## 6. 最深的冲突需要三层叠加：clean 富度 ⇄ attack 防御

[深读 4](04_richness_defense_tension_and_sft_ceiling.md) 证明 clean 富化 SFT 会侵蚀身份防御（真破功 step0 16.2% → 富化后 ~40%），且这是行为空间里的 Pareto 张力，不是数据量问题（unique defense 120→2686，22×，真破功不降反升）。这个最深的冲突，**任何单一机制都解决不了**，v6.5→v6.10 整条弧其实是在叠三层机制：

1. **① 阶段分配**：富度归 SFT、防御归 RL（别在 SFT 里同时硬追，那是 whack-a-mole）。
2. **③ per-source 解耦**：RL 里 clean 只拿 clean_q + 紧 KL（守 SFT 注入的富度），attack 才拿 rm + break_pen（改防御）。
3. **② 字典序门控**：attack 侧 break_pen −5 碾压 clean_q，保证"不破功"先于"有戏"。

外加 [深读 5 门 D](05_when_to_move_from_sft_to_rl.md) 的 **canary 门**（step30-50 先验证 clean 不退再放行）当兜底。**一个冲突越深，需要叠的机制层数越多**——这就是为什么 richness⇄defense 花了整条 v6.x 弧，而"动作 vs 对话"在 SFT 选择器里调个权重就够了。

---

## 7. 普适化：多目标协调的一页速查

```
对每一个目标，先问三件事：
  1) 它的梯度/信号在哪一层？        → 没有就别在这层追（机制①，换 stage）
  2) 它是"偏好"还是"约束"？
       偏好(可替代)  → 加权和，但盯放大器（机制②a）
       约束(不可破)  → 字典序门控，别塞进加权和（机制②b）← reward hacking 高发区
  3) 它在不同输入上要求一致吗？
       不一致        → per-source 解耦（不同 reward + 不同 KL）（机制③）

冲突越深 → 叠的机制越多：
  浅(动作 vs 对话)        = 单层加权和
  中(安全 vs 配合)        = 字典序门控
  深(富度 ⇄ 防御)         = 阶段分配 + per-source + 字典序门控 + canary
```

**最值钱的判断**：拿到一个"模型在 A 上好了 B 就退"的现象，先别调权重——先判断这是**该换层（①）、该换聚合方式（②）、还是该按输入解耦（③）**。本项目里调错层的代价（v6.7 的 100 步、v6.8 的 187%、anti_refusal 的反向训练）都远大于调对层之后的微调。
