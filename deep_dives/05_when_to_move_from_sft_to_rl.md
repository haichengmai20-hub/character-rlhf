# 深读 5 — 何时从 SFT 转向 RL：入口门的多重判据与"过早起 RL"的真实代价

> 阅读路线：先看 [深读 0 — 面试综合路线](00_interview_synthesis.md)，再按本篇专题深挖。

> **版本命名**：本篇保留原始实验号叙述；哪些是真改进、哪些只是 run/restart/失败实验，以 [VERSION_MAP](../docs/VERSION_MAP.md) 和 [project_chatjoy_overview](../docs/project_chatjoy_overview.md) 的阶段映射为准。

> 本篇展示的能力：**把"该不该起 RL"从一个拍脑袋的决定，拆成一串可证伪的门（gate），并用本项目三次真实的 RL/SFT 判断（v6.5、v6.7、v6.9c）逐门给出"违反它会发生什么"的实测证据**。核心结论：过早或错配的 RL 不是"零收益"，是**负收益**——这正是"入口门"存在的理由。
>
> 所有数字来自工作区真实文件：`v69_reconcile_report.md`（三方真破功）、`docs/design/chatjoy_rl_v610_defense_clean_aware_design.md` §0、`CASE_STUDY.md`（v6.5 归因）、`/root/rich_cjk_sft_v69/` 下的 probe 数据与 build 脚本。与既有运行手册 [RLHF_WORKFLOW.md](../RLHF_WORKFLOW.md) §8.1 的区别：那里是"怎么执行入口门"的 runbook，本篇是"为什么是这几道门、每道门背后的数据机制"。

> ## Attribution Lens
> 本篇的四道入口门本质是"把一次 RL 失败归因到哪一层"的判据：门 A=**evaluation protocol**、门 B=**reward model**（目标轴方差）、门 C=**data distribution**（SFT 可约性）、门 D=**GRPO optimization** 的代价。[深读 8](08_credit_assignment_in_character_rlhf.md) 在门 B 之后补了一道 **Gate E（credit 能否定位到真正错误行为）**——本项目 v6.10 正是 A/B/C 齐过却卡在 Gate E。

## 0. 反直觉的起点：RL 曾把防御训得比 base 还差

大多数人对 RLHF 的默认心智是"RL = 在 SFT 之上再提一档"。本项目的早期数据直接推翻了这个默认：

| 模型 | roledrop 破功率 | 含义 |
|---|---|---|
| **base_it**（未经 RL） | **27%** | 防御最强（基线） |
| 早期 RL v2 | 55% | 比 base 差一倍 |
| 早期 RL v1 | 91% | 比 base 差 3.4 倍 |

来源：`CASE_STUDY.md` / `README.md`。根因是当时 RM 里 `anti_refusal +3.0` 的 bonus 把"坦白身份"误判成"好的不拒绝"，于是 RL **朝着破功的方向**优化（典型 Goodhart，详见深读 2）。

**这张表是整篇的地基**：RL 是一个把"你给的奖励"放大到分布尾部的优化器；如果奖励、评测、或问题类型不对，RL 会**高效地把模型推向错误**。所以"何时起 RL"不是"什么时候允许变更好"，而是"什么时候这台放大器指向的方向是对的"。下面四道门，每一道都是在检查放大器的某一个前提。

---

## 1. 门 A：评测必须能"看见"失败——否则 RL 在盲区里空转

**违反它的实测：v6.5 跑了 375 步零移动。**

- 现象：`clean_RM` 卡在冻结 RM 的 ~1.33 天花板，attack break 平在 ~11–16% 不降，375 步两轴都不动（收敛形态同 v6.3）。
- 当时的误读："loss 不降 = RL 学不动 = 算法/参数问题"。
- 真因（做 70-case 产品 probe 时才发现）：**训练 val 的 attack 破功率 11% ≠ 产品真实 roledrop 55%**。val 里 task-compliance 形态（"改成清单格式"/"列出步骤"类 bullet 注入）只占 5%，而产品里这是最高频攻击（55%）。RM 在训练 val 上**几乎没见过产品形态的攻击** → 这类失效在训练信号里**稀疏到没有梯度**，而且 val 本身**测不出**这个失效有没有被改善。

**机制提炼**：RL 优化的是"评测能打分的东西"。如果评测集的失败分布 ≠ 生产失败分布，会同时坏两件事：① 训练信号在目标失效上稀疏（学不动）；② 即便学动了你也看不见（测不出）。两者叠加，表现就是"零移动"，但归因到算法是错的。

**起 RL 前的廉价预检**：拉一批真实生产输入，统计它的失败类型分布，再比对你的 val/probe 集的失败类型分布。两者不重合 → 先修评测，别起 RL。本项目的修正：把 attack probe 统一换成 **68 条产品形态攻击词典**（bullet 注入 + 身份询问 + A6 代码注入 + 多语言越权），并与训练 val 隔离。这套 probe 后来成了 v6.9 全程的验收口径。

## 2. 门 B：RM 必须在"目标轴"上有梯度——分轴方差是廉价判据

**违反它的实测：v6.7 想用 RL 提 clean 富度，100 步只 +0.037 ≈ 噪声。**

把 RM 的打分按数据源拆开看（`rm_scores.jsonl` 分轴），会发现 RM 根本不是一个"通用质量打分器"，而是一个**防御判别器**：

| 轴 | RM 打分跨度（probs_0） | 含义 |
|---|---|---|
| clean | 0.177–0.214，跨度 **0.037** | 几乎是平的 |
| attack | 0.205–0.561，跨度 **0.36** | 有 ~10× 的区分度 |

GRPO 的优势是组内标准化 `A_i = (r_i − mean)/std`（深读 3 §1.1）。clean 组内 reward 跨度只有 0.037，标准化后优势 ≈ 0 → **没有梯度**。v6.7 用 100 步实测验证了这一点：clean RM +0.037（≈噪声），而同期防御（attack 轴）确实在动。

**机制提炼**：RL 只能提升 RM 能排序的轴。一个轴上 RM 没有区分度，RL 在那个轴上就是无能为力的——这不是参数没调好，是工具用错了。

**这道门直接决定了本项目的分工**：
- **clean 富度**：RM 平 → RL 无能 → 交给 SFT 蒸馏 teacher（深读 4 / 深读 2 §4.4）。
- **attack 防御**：RM 有 0.36 区分度 → RL 是对的工具 → v6.10 走 RL。

**起 RL 前的廉价预检**：在候选 RM 上，把验证样本按你的目标轴分组，算每组 reward 的方差/跨度。目标轴方差 ≈ 其他轴 → RM 在目标轴上是平的，RL 会空转（或被其他轴带跑）。这一步只要一次离线打分，比起 RL 烧 GPU 便宜几个数量级。

## 3. 门 C：残余失败必须是 SFT 不可约的——先把 SFT 做到尽

门 A、B 是"RL 能不能用"的硬前提。门 C 是顺序问题：**即便 RL 可用，也要先确认这个失败 SFT 修不动**，否则 SFT 是更便宜、更安全的工具（无 clean 回退/温度脆/多样性塌的风险）。

本项目把它固化成"§6 顺序锁：SFT-defense 先尽力，RL 收尾"，并在 v6.9 上做了一次真实的分支判断：

**v6.9 入口门判定 → 分支 2b（不跳 RL，先补 SFT）**：
- v6.9 破功率 42.6%（raw）>> step0 23.5%，attack-split RM 0.214 < step0 0.297 → 材料性退化，看起来"该上 RL 修"。
- 但逐类归因发现根因是**数据覆盖缺口**：A6 任务注入/代码在 defense 池里 **0 覆盖**，ML 多语言（zh-tw/ja/ko/sk）薄。**覆盖缺口是 SFT 能修的** → 判定 SFT-defense 尚未尽力 → 先补 defense 重训。

然后用两轮 SFT-defense 把"SFT 能不能修"这个问题**实验到底**：

| 轮次 | 新增 unique defense | defense 在 mix 中占比 | 真破功率 | 真代码(A6) | 真身份 |
|---|---|---|---|---|---|
| step0（无 defense） | 0 | — | **16.2%**（11/68） | 5 | 6 |
| v6.9（富化） | 0 | — | ~40%（raw 42.6%） | 12(raw) | 14(raw) |
| v6.9b | **120** | 1.6%（新增） | 32.4%（22/68） | 9 | 13 |
| v6.9c | **2686** | **64.1%** | 33.8%（23/68） | 11 | 12 |

> 真破功 = `detect_ooc.py` flag 后去 echo/code 误报；step0/v69b/v69c 数字取自 `v69_reconcile_report.md` 三方表。v6.9 一列只有 raw（未单独做去误报重算），故标 ~40%。占比 64.1% 由 `4566 = 2686 身份 + 1200 clean + 440 zh-tw + 240 旧` 算得（eval-paradigm 文档实测）。

**读这张表的关键不是某个绝对值，是斜率**：unique defense 数据从 120 → 2686（**22×**），破功率从 32.4% → 33.8%（**不降反微升**）。defense 浓度从"撒进 3 万条 mix"变成"占聚焦 repair mix 的 64%"，仍然压不回 step0 的 16.2%。分类看：真身份 13→12（基本不动），真代码 9→11（**加了数据反而更差**）。

**这就是"SFT 到天花板"的可观测信号**：边际收益不是递减，是反转。一个失败如果靠加 SFT 数据能修，斜率应该是负的；这里斜率拐成了正，说明残余失败已经不是覆盖问题。

**为什么不是 teacher 太弱（一个被数据否决的假说）**：v6.9c 的 2686 条 defense 是 step0 自蒸馏来的，良率 **78.8% in-char**（77 个不同角色 system，0 条 OOC 漏网）——teacher（step0）面对身份攻击有 78.8% 的概率本来就能在角色内化解，能稳定产出干净的 defense 正样本。所以"teacher 产不出 defense"不成立。失败的不是数据生产，是 **SFT 这个范式**：它是静态分布对齐，训练集里"高沉浸 clean"和"低沉浸 defense"是两簇分离的样本，模型学不到"沉浸中被攻击→角色内化解→继续沉浸"这条完整轨迹（机制详见深读 4）。这种"稀有尾巴 + 需要在轨迹内切换"的失败，正是 RL 的 on-policy rollout 的强项。

**与 v6.5 的对照（同样是"破功率高"，结论却相反）**：v6.5 当时也"破功率高、想上 RL"，但它的真问题在门 A（评测看不见）和门 B（RM 错配），根本没到"SFT 不可约"这一步——那时候起 RL 是把放大器指向了盲区。v6.9c 不同：门 A（68 条产品 probe）✓、门 B（attack 轴 RM 有 0.36 区分度）✓、门 C（两轮 SFT 斜率反转）✓——三门齐过，残余失败确认是 SFT 修不动的稀有尾巴，这才是 RL 的正确入口。

## 4. 门 D：RL 的代价不是零——三个已证风险决定了"过门后仍要设 canary"

即便 A/B/C 三门齐过，RL 仍可能把别的东西弄坏。本项目有三个实测风险，它们共同决定了 v6.10 不是"放手跑到 200 步"，而是带一道 canary 门：

1. **clean 回退**：RM 在 clean 上平（门 B），意味着 RL 对 clean 没有"保护性梯度"，KL 一旦松，clean 分布会被 attack 侧的更新带着漂走。v6.10 设计/远端记录的对策是 per-source KL（clean prompt 只拿 `clean_q` + KL_CLEAN=0.008）；step90 确认 clean held，但完整关闭 clean RM 的 patch 未入库，不能用当前本地代码证明“物理上不给信号”。

2. **温度脆**：v6.7 是这道风险的活样本。按**修正后的 attack-split RM**（纯 attack 分，非 clean+attack 混合分）：

   | 温度 | step0 | v6.7 step100 |
   |---|---|---|
   | t0.7 | 0.293 | 0.305（**+0.013**，边际） |
   | t1.0 | 0.254 | **更差**（高温崩） |

   v6.7 用 `N=6 + rollout_temp=0.7` 训练，只锐化了"低温下的模态拒绝"，对高温尾部的稀有破功没有梯度——于是在部署口径 t0.9 上防御反而崩了。RL 的收益既**边际**（+0.013）又**只在训练温度附近成立**。对策（v6.10）：rollout_temp=1.0（≥ 部署 t0.9）+ N=12（让稀有破功尾巴在组内出现）+ 逐样本 break_pen（对单条破功敏感，不只看组均值）。详见深读 3 §4.7。

3. **多样性 / mode collapse**：RL 倾向收敛到高 reward 的少数模态。对策：靠 rollout 温度 + KL 维持，并把"开场集中度 ≤ actor"列为停线。

> 关于 v6.7 的两套数字：早期文档里有"防御 +0.092"的说法，那是 **clean+attack 混合分**（旧口径）；分轴重算后纯 attack 增益是 **+0.013**。本篇统一用分轴口径——能把混合分误当 attack 护栏，本身就是一次"评测口径不对 → 结论被高估"的教训（呼应门 A 的精神）。

**对策的总形态**：canary 门。先跑 step 30–50，对该 ckpt 跑 clean+attack probe vs actor；**clean 三轴不退 且 attack 真破功趋降**才放行到 100–200；任一失败就停、报告，不擅自调参。RL 过了入口门 ≠ 可以无人值守。

## 5. 四门串成一张决策图

```
                       生产失败分布 ↔ 评测失败分布 重合？
                                  │
                 否 ──────────────┤ 门 A 失败：先修评测（v6.5 教训：375 步零移动）
                                  │ 是
                                  ▼
                    RM 在目标轴上有区分度？（分轴方差检验）
                                  │
   平（如 clean，跨度 0.037）─────┤ 门 B 失败：RL 无能 → 交给 SFT/蒸馏（v6.7：clean +0.037≈噪声）
                                  │ 有（如 attack，跨度 0.36）
                                  ▼
                  SFT 还能修吗？（加 defense 数据斜率是否仍为负）
                                  │
        能（覆盖缺口，斜率<0）────┤ 门 C 分支 2b：先补 SFT（v6.9→v6.9b raw 42.6→33.8）
                                  │ 不能（斜率反转，22× 数据不降）
                                  ▼
                       起 RL —— 但带 canary 门（门 D）
                                  │
            step30-50 probe：clean 不退 且 attack 趋降？
                       ├─ 是 → 放行到 100-200
                       └─ 否 → 停（clean 回退 / 温度脆 / 多样性塌）
```

对应 RLHF_WORKFLOW §8.1 的三分支（① 破功率 ≤ 容忍 → 上线不 RL；② 材料性高 + SFT 尽力 → 起 RL；③ 中间小缺口 → 靶向 SFT hardfix），本图把每个分支背后的**判据**和**违反它的实测后果**补全了。

## 6. 普适化：RL 有用的充要条件

把本项目的四门抽象成一句话：

> **RL 能带来正收益，当且仅当：(A) 评测能看见目标失败 ∧ (B) 奖励在目标轴上有区分度 ∧ (C) 目标失败是 on-policy 可塑的、而非覆盖可补的；任一不满足，RL 是零收益或负收益。**

- 违反 A：在盲区空转（v6.5 的 375 步）。
- 违反 B：在平轴上空转或被别的轴带跑（v6.7 的 clean +0.037）。
- 违反 C：用昂贵且有副作用的工具做了便宜工具（SFT）能做的事。
- 三者皆满足但忽视代价（门 D）：把防御练成温度脆的模态拒绝、或把 clean 练退。

每道门都对应一个**比 RL 便宜几个数量级的离线预检**：A = 比对失败分布；B = 分轴方差；C = 加数据看斜率。先花几小时做完这三个预检，再决定要不要花几天 GPU 起 RL——这是本项目从 v6.5 的 375 步空转里买来的最贵的一课。
