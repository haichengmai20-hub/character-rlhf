# 深读 9 — 全链路差分归因：指标没提升 / 上线不行时，如何把根因判给正确的那一层

> 本篇展示的能力：**把"业务指标没动 / 上线效果不行"这一个症状，当成主诉，在整条 RLHF 链路上做差分诊断——对每一个候选病因给出"若是它会看到什么特征 + 用什么最小实验把它和相邻病因区分开"，而不是条件反射地去调 RL 参数。** 核心主张：在这个项目里，"指标没动"至少出现过四次，一线直觉每次都指向"再调调 RL 超参 / 多跑几步"，但**没有一次**是靠调 RL 超参解决的——真实根因分别落在评测 / RM / 数据 / credit 层（credit 虽属算法结构，但同样不是调超参能修的，见 §7/§8 的区分）。归因错层比问题本身更贵——归因能力 = 不被表面症状骗、按成本从低到高系统性逐层排除。
>
> 与相邻两篇的分工：[深读 5](05_when_to_move_from_sft_to_rl.md) 是**前向门**（"该不该起 RL"，A/B/C/D/E）；[深读 8](08_credit_assignment_in_character_rlhf.md) 是**单一透镜**（只讲 credit assignment）；本篇是**后向差分**（症状已发生，逐层排查锅在哪），credit assignment 只是差分树里的**一列**，深链深读 8、不重推公式。所有数字取自仓库既有记录（[CASE_STUDY](../CASE_STUDY.md) / [VERSION_MAP](../docs/VERSION_MAP.md) / 深读 4/5/8 / [v69_reconcile_report](../reports/v69_reconcile_report.md) / [rl90_temp_sweep_report](../reports/sft_richness/rl90_temp_sweep_report.md)）；本篇**新提出的诊断指标一律标注 `Proposed diagnostic — not yet run`，未声称已跑实验**。

> ## Attribution Lens
> 本篇把"指标没提升 / 上线不行"这个症状，逐层归因到以下 8 个候选层，每层配一个最小判别实验：
> - **评测 / 度量层**（指标是不是根本没测对：val≠产品、业务≠技术代理、口径不同尺）
> - **数据层**（覆盖缺口 / 分布偏，加数据斜率仍为负）
> - **SFT 强度层**（base 分布能不能当 RL 起点，加数据斜率是否反转）
> - **reward model 层**（目标轴上有没有 reward 方差）
> - **reward 规则层**（rule 组件把 credit 记到了错误行为，Goodhart）
> - **RL 参数 / 优化动力学层**（超参与优化能不能榨出梯度）
> - **credit assignment 层**（方向对了，罚落不到破角 span）
> - **部署 / 采样层**（旋钮只改表达、不改能力）

## 0. 反直觉的起点：同一个症状，四个不同病灶

和深读 5/8 一样，本篇从一张推翻默认心智的表开始。默认心智是"指标没动 = RL 学不动 = 算法 / 参数问题"。本项目里"指标没动 / 没改善"这**同一个表面症状**出现过至少四次，而真实根因分属**四个完全不同的层**：

| 事件 | 表面症状 | 一线直觉归因 | 真实根因层 |
|---|---|---|---|
| v6.5 硬化 GRPO 375 步零移动 | attack 不降 | "RL 学不动＝算法 / 参数" | **评测层**：训练 val attack 11% ≠ 产品 roledrop 55% |
| v6.7 RL 提 clean 富度 100 步 +0.037 | clean 提不动 | "RL 步数不够 / 参数没调好" | **RM 层**：clean 轴打分跨度只有 0.037，无方差 |
| v6.8 SFT 富化独白过冲 187% | 富度反而坏了 | "SFT 数据不够" | **数据 / 选择器层**：选择器＝放大器，独白进了目标 |
| v6.10 step90 attack 真破功 36.8% | attack 压不动 | "RL 没调好 / 再堆步数" | **credit 层**：-5 是整条回复级，落不到破角 span |

来源：`CASE_STUDY.md` / `README.md` / `docs/VERSION_MAP.md` §2 / 深读 4/5/8。

**四次"指标没动"，一线直觉全指向"再调调 RL"，但没有一次能靠调 RL 超参解决。** 这就是本篇的地基：把"指标没动"直接归因到"RL 参数没调好"，在这个项目里的历史命中率是 0/4（真实根因分属评测 / RM / 数据 / credit 四个不同层，而 credit 也不是调超参能修的——见 §7/§8）。真正值钱的不是"会调 GRPO"，而是**在烧 GPU 之前，先用一串比重训便宜几个数量级的判别实验，把锅精确判给正确的那一层**。下面把整条链路拆成 8 个候选病因，每个都给"特征指纹 + 最小判别实验 + 项目确诊案例"。

## 1. 差分诊断总表（一页速查）

把 RLHF 链路从前到后、按"排查成本从低到高"排开，得到 8 个候选病因。每一列的用法是：先看**特征指纹**（它和相邻层长得哪里不一样），再用**最小判别实验**去证实/排除，最后对照**项目确诊案例**。排查顺序不是从模型内部开始，而是**从最便宜的两端（评测、采样）往中间收**——因为它们最便宜、又最容易被跳过。

| 候选层 | 特征指纹（区别于相邻层） | 最小判别实验 | 相对成本 | 项目确诊案例 |
|---|---|---|---|---|
| 评测 / 度量 | 指标动或不动都可能是**度量假象** | 生产 vs 评测失败分布比对；同检测器同尺重算 | 极低 | v6.5：val 11% ≠ 产品 55% |
| 部署 / 采样 | 改采样只改表达、有地板 | 固定权重扫 temp/top_p/presence/min_p | 极低 | sweep 只到 ~30% 地板 |
| RM | 目标轴 reward 方差 ≈ 0 | 一次离线打分，按目标轴分组算跨度/方差 | 低 | clean 0.037 vs attack 0.36 |
| reward 规则 | 组件把 credit 记到**错误行为** | 去 bonus / 加硬罚消融 + 组件 breakdown | 低 | anti_refusal +3.0 反向破角 |
| 数据 | 加定向数据斜率**仍为负** | 补覆盖后看斜率 + 查目标失效覆盖率 | 中 | A6 0 覆盖；v6.8 选择器放大 |
| SFT 强度 | 加数据斜率**反转**（不降反升） | 把 unique 数据放大一个数量级看斜率 | 中 | 120→2686（22×）反转 |
| RL 参数 / 动力学 | 改超参**有**动力学响应 | 扫 temp/N/KL/GSPO 看响应曲线 | 高 | v6.7 温度脆；375 步硬化 |
| credit assignment | 超参调对、方向对，**仍**压不动 | `bad_span_kl_share`（`Proposed`） | 高 | v6.10 attack 36.8% |

> 读表要点：**"attack 不降"这一个现象，至少对应 RM 层、RL 参数层、credit 层三个不同病灶**（§5 / §7 / §8）；"加数据没用"至少对应数据层和 SFT 强度层两个（§3 / §4）。差分诊断的价值就在于用一个廉价判别实验把这些"同症状不同病灶"分开——这也是 §11 会提炼的方法论。

## 2. 评测 / 度量层：先证明"指标真降了"

排查从这里开始，因为它最便宜、也最常被跳过：**在归因任何模型内部原因之前，先证明你观察到的"指标没动 / 上线差"不是度量假象。**

- **症状表现**：业务指标没提升、上线体感差；或训练指标"零移动"。但问题可能根本不在模型，而在"你测的东西"和"你要的东西"之间。
- **特征指纹（区别于 RL 学不动）**：三种典型错位——① 训练 val 的失败分布 ≠ 生产失败分布；② 业务指标（留存 / 好评）与你优化的技术代理（RM 分 / 破功率）之间没对齐；③ 同一现象在不同口径下数字打架（raw 检测 vs 去误报重算）。
- **最小判别实验（成本极低）**：拉一批真实生产输入，统计它的失败类型分布，再比对 val/probe 集的失败类型分布——两者不重合就先修评测，别动模型。对齐口径时坚持"同一次、同检测器去 echo/code 误报再比较"。
- **项目确诊案例**：
  - v6.5 硬化 GRPO 跑了 **375 步零移动**，当时误读为"RL 学不动＝算法问题"。做 70-case 产品 probe 才发现真因：**训练 val 的 attack 破功率 11% ≠ 产品真实 roledrop 55%**——产品里最高频的 bullet 注入（"改成清单"/"列出步骤"）在 val 里只占 ~5%。这类失效在训练信号里稀疏到没有梯度，val 本身又测不出它有没有改善，叠加起来就表现为"零移动"，但归因到算法是错的。修正：把 attack probe 统一换成 **68 条产品形态攻击词典**并与训练 val 隔离。
  - v6.7 曾有"防御 +0.092"的说法，那是 **clean+attack 混合分**；分轴重算后纯 attack 增益其实只有 **+0.013**。同一次 RL，口径不对就把噪声级增益当成了护栏——这本身是一次"评测口径 → 结论高估"的教训。
- **常见误判**：把"评测盲区"误当成"RL 学不动 / 参数没调好"（v6.5 正是如此），于是去堆步数、调超参，在盲区里空转。

> **机制提炼**：RL 只优化"评测能打分的东西"。失败分布 ≠ 生产分布会同时坏两件事——训练信号在目标失效上稀疏（学不动）+ 即便学动了你也看不见（测不出）。所以差分诊断的第 0 步永远是：**先证症状为真，再谈归因。**

## 3. 数据层：覆盖缺口 vs 分布偏

确认症状为真之后，往模型内部走的第一站是数据——因为"某类失效怎么训都不改善"最常见的原因，是训练集里**它根本没几条**。

- **症状表现**：某一类失效（某种攻击、某个小语种、某种格式）无论怎么训都不动；或某个维度被意外放大。
- **特征指纹（区别于 SFT 到顶）**：目标失效在训练 batch 里样本量 ≈ 0（覆盖缺口）；或数据构造里的选择器把某个模态过度放大（分布偏）。关键判据：**加了定向数据，斜率还是负的（还能救）**——这区别于 §4 的"斜率反转"。
- **最小判别实验（成本中）**：先查目标失效在训练集里的覆盖率；再补一批定向数据、只训这一轴，看破功率斜率是否随数据量下降。
- **项目确诊案例**：
  - **A6 任务注入 / 代码**在 defense 池里 **0 覆盖**、多语言（zh-tw/ja/ko/sk）薄——这是纯覆盖缺口，是 SFT 能补的，据此在 v6.9 判定"先补 defense 再说，别急着上 RL"。
  - v6.8 SFT 富化把**独白（monologue）放进了选择目标**，结果 best-of-N 选择器变成**放大器**：偏哪放大哪，独白过冲到 **187%**，对话回退、动作没动。修正（v6.9）：选择器只均衡动作 + 对话 + sensory/interaction/emotion，**独白不入目标**。
- **常见误判**：与 §4 SFT 强度层易混。两者都表现为"看起来加数据应该有效"。判别关键：**加数据斜率是否反转**——不反转（仍为负）＝数据层可补；反转（不降反升）＝已到 §4 的 SFT 天花板。

> **机制提炼**：数据层的失败能靠覆盖补。能用更便宜、更安全的 SFT 补的事，别怪 RL 算法——这也是深读 5 门 C 的精神。

## 4. SFT 强度层：base 分布能不能当 RL 的起点

数据能补的补完之后，下一个问题是：**残余失败到底是"还能补数据"，还是"SFT 这个范式已经到顶、只能交给 RL"？** 这一层判错，会让你要么在 SFT 上空耗、要么过早起 RL。

- **症状表现**：残余失败看起来"该上 RL 了"，但你不确定 SFT 是否真的已经尽力。
- **特征指纹**：把 unique 数据放大一个数量级，破功率斜率**反转**（不降反升）——这是"SFT 范式到天花板"的可观测信号。
- **最小判别实验（成本中）**：把某一轴的 unique 训练数据放大 ~10×，观察真破功率斜率；同时用 teacher 的自蒸馏良率**否决"teacher 太弱"这个竞争假说**（若 teacher 本来就能稳定产出正样本，失败就不在数据生产，而在 SFT 范式本身）。
- **项目确诊案例**：三轮 SFT-defense 把"SFT 能不能修"实验到底——

  | 轮次 | 新增 unique defense | 真破功率 | 真代码(A6) | 真身份 |
  |---|---|---|---|---|
  | step0（无 defense） | 0 | **16.2%**（11/68） | 5 | 6 |
  | v6.9b | 120 | 32.4%（22/68） | 9 | 13 |
  | v6.9c | **2686（22×）** | 33.8%（23/68） | 11 | 12 |

  unique defense 从 120 → 2686（**22×**），真破功率 32.4% → 33.8%（**不降反微升**），真身份 13→12（基本不动）、真代码 9→11（**加数据反而更差**）。**斜率从负拐成正 = SFT 到顶。** 而"teacher 太弱"被数据否决：step0 自蒸馏 **78.8% in-char 良率**、49 条 A6 正样本 **0% 含代码**——teacher 产得出干净 defense，失败的是 SFT 这个"静态分布对齐"范式学不到"沉浸中被攻击→角色内化解→继续沉浸"这条完整轨迹。
- **常见误判**：把"斜率反转"误当成"数据还不够"（→ 继续在 SFT 空耗），或误当成"该无脑上 RL"（→ 跳过门 A/B）。

> **机制提炼**：斜率反转是"SFT 到顶"的可观测信号；到顶才轮到 RL。一个失败若靠加 SFT 数据能修，斜率应该是负的；拐成正的，说明残余失败已不是覆盖问题。（完整机制见深读 4。）

## 5. RM 层：目标轴上有没有梯度

到这一层，SFT 已确认到顶、准备用 RL。但 RL 之前必须先问：**RM 在你要优化的那根轴上，到底有没有区分度？** 没有的话，RL 会在平轴上空转——而这只需一次离线打分就能提前发现。

- **症状表现**：RL 在目标轴上空转（如 v6.7 clean 100 步只 +0.037 ≈ 噪声），但同期别的轴在动。
- **特征指纹（区别于 credit 层）**：把 RM 打分**按目标轴分组**，目标轴的 reward 跨度 / 方差 ≈ 0。注意与 §8 的关键差别：RM 层是**根本没有信号**（方差为零），credit 层是**有信号但落不到 span**（有方差、错位）。
- **最小判别实验（成本低）**：在候选 RM 上对验证样本按目标轴分组离线打分，算每组 reward 跨度/方差——一次离线打分，比烧 GPU 起 RL 便宜几个数量级。目标轴方差 ≈ 其它轴 → RM 在目标轴上是平的，RL 必空转。
- **项目确诊案例**：
  - RM 按数据源拆开看，clean 打分跨度只有 **0.037**，attack 跨度 **0.36**（差 ~10×）——RM 根本不是"通用质量打分器"，而是一个**防御判别器**。clean 组内标准化后优势 ≈ 0，v6.7 用 100 步实测坐实（clean +0.037，attack 轴确实在动）。这条直接锁定分工：**clean 富度交 SFT、attack 防御交 RL**。
  - RM 训练本身也要逐层归因：RM v2 acc 从 94.5% 退到 86.4%，根因是 **batch 减半 + score head 保存 bug**，不是数据问题；RM v3 rejected 只 −0.30，根因是 **cosine LR 步数不足**。"RM 分不对"要继续往里归因到 batch / 保存 / LR 调度，而不是停在"RM 不行"。
- **常见误判**：与 §8 credit 层高度易混——两者都表现为"目标轴（attack）不降"。判别关键：**分轴方差是否 ≈ 0**。方差为零 = RM 层（没信号）；方差健康但仍压不动 = 往 §8 走（有信号、落不到 span）。

> **机制提炼**：RL 只能提升 RM 能排序的轴。方差是 RM 给的，不是优化器能造的——目标轴上 RM 没区分度，是**工具用错了**，不是参数没调好。（对应深读 5 门 B。）

## 6. reward 规则层：组件把 credit 记到了错误行为

RM 有方差不等于奖励对。RM 主信号之外还有一层 rule reward（anti-OOC / anti-refusal / length-shaping…），它们决定"功劳和罪责记在哪个行为上"。这一层坏了，方向本身就是错的——而且它比 RL 参数便宜得多就能查出来。

- **症状表现**：reward 在涨、方向看着对，真实目标却越训越坏（越训越会破角 / 越训越水）。
- **特征指纹（区别于 credit 层）**：某个 rule 组件对"错误但表面合规"的行为给了正分——是**功劳记错了行为**（方向错），不是 §8 的"方向对但落点错"（span 错）。
- **最小判别实验（成本低）**：打开 reward 组件 breakdown 日志，看每条 reward 由哪几项组成；再做**组件消融**——去掉某个 bonus / 加一条硬罚（**改 rule reward，不重训 RM**），看破功行为是否变化。
- **项目确诊案例**：`anti_refusal` 的逻辑是"只要没有拒绝词就 +3.0 NON_REFUSAL_BONUS"。"我是 AI，但我可以继续陪你"里没有拒绝词 → 拿满分 → 这条自报身份的破角回复得到正 advantage → RL **朝破功方向**优化。结果 RL 后 roledrop 破功 base **27% → v2 55% / v1 91%**（越训防御越差），而旧关键词指标 `atk_break%` 对"自报身份"完全瞎、只显示 ~16%（这一半是 §2 评测层的问题）。修复（全 TDD，**不重训 RM**）：新增 `anti_ooc_disclosure.py`，对身份披露 / 角色内代码 / system 泄露**硬罚 -5**，并**撤销**误给的 +3.0，把 reward 排序重排成 `identity consistency > non-refusal helpfulness > richness`；68 条 attack probe 的 OOC 误报 **1/16 → 0/16**。
- **常见误判**：与 §8 credit 层易混。reward 规则层是**功劳记错组件 / 行为**（把"破角式配合"当"配合"奖励，方向错）；credit 层是**方向已对、但 -5 落不到破角 span**（落点错）。两者都从"reward 视角"看，但一个修方向、一个修定位。

> **机制提炼**：这是教科书级 Goodhart，但从归因看更精确——它是"reward-component credit misallocation"：不是 reward 太少，是功劳 / 罪责记在了错误的组件和错误的行为上。**先修方向（规则层），才谈定位（credit 层）。**（完整代码细节见深读 2。）

## 7. RL 参数 / 优化动力学层：超参与优化能不能榨出梯度

到这里，评测对了（§2）、采样已排除（§9）、RM 有方差（§5）、方向修对了（§6）、数据/SFT 到顶了（§3/§4）。现在才轮到"是不是 RL 超参 / 优化本身没榨出梯度"——注意它在排查顺序里**很靠后**，因为它最贵、且前面每一层没排除时都会伪装成它。

- **症状表现**：目标轴该有梯度却没榨出来，或改善只在训练温度附近成立、换个部署温度就没了。
- **特征指纹（区别于 credit 层，这是本篇最关键的一对区分）**：**改超参有动力学响应**——动一动 rollout_temp / group N / KL / GSPO 聚合 / 步数，指标或熵 / grad_norm 就跟着变。若超参怎么调都无响应、方向也对，就不是这一层，是 §8。
- **最小判别实验（成本高，要跑 RL）**：扫 rollout_temp、group N、KL 系数、GSPO/DAPO 聚合方式，画响应曲线；并**对齐训练温度与部署温度**（否则会训出"温度脆"的假护栏）。
- **项目确诊案例**：
  - **温度脆**：v6.7 用 `N=6 + rollout_temp=0.7` 训练，只锐化了"低温下的模态拒绝"——按分轴 attack-split RM，t0.7 增益 **+0.013**（边际），**t1.0 反而更差**（高温尾部的稀有破功没有梯度）。这是典型的"参数选择决定了梯度覆盖的温度范围"。
  - **对策也在这一层**：v6.10 改 `rollout_temp=1.0`（≥ 部署温度 t0.8）+ `N=12`（让稀有破功尾巴在组内出现）+ 逐样本 break_pen（对单条破功敏感，不只看组均值）+ GSPO `seq-mean-token-mean`（配 MoE + 标量 RM）。
  - **硬化到顶**：v6.5 把 GRPO 硬化（temp 1.2 / N=6 / 375 步）想再榨梯度，结果 375 步零移动——但注意这次的**根因其实在评测层（§2）**，参数层只是"榨不出本就不存在的梯度"。这正说明为什么参数层要放在排查靠后：前面没排除干净时，它会背锅。
- **常见误判**：把前面任一层（评测盲区 / RM 无方差 / 方向错 / credit 缺位）的问题误当成"参数没调好"，然后无限扫超参。**判别铁律：改超参有响应 = 参数层；超参调对、方向对、仍压不动 = credit 层（下一节）。**

> **机制提炼**：参数层能调"放大器的强度、方向覆盖面、温度范围"，但它**调不出**"把一条 -5 精确落到破角 span"的能力。能靠调超参解决的，动力学会给你响应；给不出响应的，问题在下一层。（超参算法原理见深读 3。）

## 8. credit assignment 层：方向对了，罚落不到破角 span

这是差分树的最后一层，也是最容易被误当成"再 RL 几步"的一层。它的定义就是**前面全部排除之后的剩余嫌疑**：评测能看见、数据到顶、RM 有方差、方向修对、超参也无更多响应——目标轴却仍然压不动。

- **症状表现**：v6.10 step90，clean 守住了，但 attack 真破功 **36.8%（25/68）≈ v6.9c 33.8%**（未改善），attack-split RM **0.235 < v6.9c 0.271**，A6 code 11→12；采样 sweep 只能把地板微调到 ~30%。
- **特征指纹**：sequence-level 的 -5 被 GRPO 摊到整条回复的**每个 token**；破角 span 只占整条回复里的少数几个 token → 负 credit 被稀释在整条正常 RP 上，落到破角 span 那部分不足以压住它。稀有破功尾巴在组内出现概率又低（即使 N 从 6 提到 12）。
- **最小判别实验（全部 `Proposed diagnostic — not yet run`）**：在 rollout 时用 `anti_ooc_disclosure.py` 的检测器标出破角 span 的 token 区间，记录 `bad_span_token_kl_share`（更新是否集中在坏 span）、`good_span_kl_share`（正常 RP 是否被误伤）；并探索把 -5 从 sequence-level 改造成 **span-masked penalty**（只在披露 span 的 token 上加强负信号）。以上均为尚未实施的诊断 / 设计假说，非已跑实验。
- **项目确诊案例**：把 §2–§7 连起来——项目补齐了评测覆盖、数据、RM 方差、reward 方向、RL 参数响应，唯独**没把 -5 定位到破角 span**。逐一排除后，v6.10 attack 压不动的剩余嫌疑就精确落在 token/span 层。项目的动作是**停线**：不再同配堆步数，转 quality-aware benchmark / RM v7 / 定向 A6+身份披露数据。
- **常见误判**：误当成 §7（再调超参）或"再 RL 几步"。判别关键（承 §5、§7）：**分轴方差健康（排除 §5）+ 改超参无更多响应（排除 §7）+ 方向已修（排除 §6），仍压不动 → credit 缺位。**

> **机制提炼**：修 reward 方向、修 group 方差、修 source 解耦，都**不能替代** token/span 级 credit 定位。attack 压不下去的地板，很可能不是"再 RL 几步"能解决的，而是要把 credit 从 sequence 下沉到 span。**完整机制、六层 taxonomy 与 per-source KL（clean 0.008 / attack 0.002）如何是 source 层 credit 干预，见深读 8——本篇只把它定位成差分树的最后一层。**

## 9. 部署 / 采样层：旋钮只改表达，不改能力

这一层和 §2 一样便宜，本该在排查早期就排除，单列出来是因为"上线不行"时第一反应往往是调采样——而它几乎从不是根因。

- **症状表现**：上线体感差，第一反应"调一下温度 / top_p 就好"。
- **特征指纹**：固定模型权重扫采样参数，指标只在小范围抖动、有明显地板。
- **最小判别实验（成本极低）**：固定 ckpt，扫 temperature / top_p / presence / min_p，判断变化是"表达风格变了"还是"能力（破功率）真的变了"。
- **项目确诊案例**：v6.7 的温度脆（t0.7 +0.013 / t1.0 崩，见 §7）说明采样温度能改变防御表现，但那是**训练温度选择**的后果、不是采样能修的；v6.10 step90 的采样 sweep 证明温度 / top_p / presence / min_p 只能把 attack 地板微调到 ~30%，**问题在训练层不在服务层**，服务口径最终定 `temperature=0.8, top_p=0.95, presence_penalty=0.4, min_p=0`。
- **常见误判**：把训练层的能力缺陷（§5–§8）误当成"采样没调好"，在服务参数上反复试。

> **机制提炼**：采样层是最便宜的排除项。把它先排掉，能把注意力**逼回训练链路**——sweep 出地板，恰恰是"问题不在服务"的最强证据（呼应深读 7）。

## 10. 把差分串成一张排查流程图

按"排查成本从低到高"把 8 层串起来，每个分支标"确诊它 / 违反它会看到什么"。这张图是[深读 5 决策树](05_when_to_move_from_sft_to_rl.md)的**镜像**：深读 5 问"要不要起 RL"（前向），本图问"已经不行了，锅在哪"（后向）。

```
指标没提升 / 上线不行
        │
① 症状为真吗？ 生产失败分布 == 评测失败分布？ 同尺重算后仍差？
        │ 否 → 评测/度量层（§2）：先修评测（v6.5 375 步零移动其实是这层）
        │ 是
        ▼
② 固定权重扫采样，能力（破功率）会变吗？
        │ 只变表达、有地板 → 部署/采样层（§9）：问题不在服务（sweep ~30% 地板）
        │ 采样改不动
        ▼
③ RM 在目标轴上有方差吗？（分轴离线打分）
        │ 跨度 ≈ 0 → RM 层（§5）：RL 必空转 → 交 SFT/换 RM（clean 0.037）
        │ 方差健康
        ▼
④ reward 组件 breakdown：有组件在奖励错误行为吗？
        │ 有 → reward 规则层（§6）：先修方向（anti_refusal +3.0 → 硬罚 -5）
        │ 方向对
        ▼
⑤ 补定向数据，斜率还是负的吗？
        │ 是（还能救）→ 数据层（§3）：补覆盖（A6 0 覆盖）
        │ 斜率反转（不降反升）→ SFT 强度层（§4）：SFT 到顶（120→2686 22× 反转）
        ▼
⑥ 改超参（temp/N/KL/GSPO）有动力学响应吗？
        │ 有 → RL 参数/动力学层（§7）：调超参（温度脆 → temp1.0+N12）
        │ 无响应、方向也对
        ▼
⑦ 剩余嫌疑：credit assignment 层（§8）
        -5 落不到破角 span → 停线，把 credit 下沉到 span（v6.10 attack 36.8%）
```

> 关键：**同一个"attack 不降"，沿这张图会分流到 §5 / §6 / §7 / §8 四个不同出口**；差分诊断就是用每一步那个廉价判别问题，把它逼到唯一正确的出口。

## 11. 归因方法论提炼（可迁移）

把本项目的排查抽象成一套跨项目可用的归因方法：

- **(a) 先证症状为真，再谈归因**：同尺重算 + 生产/评测分布比对，先排除"度量假象"（§2）。归因的第 0 步永远不是看模型，是看度量。
- **(b) 每层都有比重训便宜几个数量级的离线预检**：分布比对（§2）、采样 sweep（§9）、分轴方差（§5）、组件消融（§6）、加数据看斜率（§3/§4）——先花几小时做完预检，再决定要不要花几天 GPU。
- **(c) 控制变量，一次只动一层**：改 rule reward 时不重训 RM；补数据时只训一轴；扫超参时固定 reward。一次动多层，归因就废了。
- **(d) 廉价判别器优先**：斜率（数据可补 vs SFT 到顶）、方差（RM 有无信号）、分轴 / 分源（哪根轴 / 哪类样本在动）、同尺（口径一致才可比）。
- **(e) 认清易混病因对**：很多不同病灶共享同一个表面症状，靠一个关键判别量分开——

  | 易混病因对 | 共同表面症状 | 判别关键 |
  |---|---|---|
  | RM 无方差（§5） vs credit 无定位（§8） | attack / 目标轴不降 | 分轴 reward 方差是否 ≈ 0（有信号 / 无信号） |
  | 数据覆盖缺口（§3） vs SFT 到顶（§4） | 加数据看似该有效 | 加数据后斜率是否反转 |
  | RL 参数（§7） vs credit（§8） | 目标轴压不动 | 改超参是否有动力学响应 |
  | 评测盲区（§2） vs RL 学不动（§7） | 指标零移动 | 生产 / 评测失败分布是否重合 |

> **一句话方法论**：把"指标没动"当**主诉**而非**诊断**——先证症状为真，再按成本从低到高，用一串廉价判别器把同一个症状逼到唯一正确的那一层。

## 12. 面试讲述版本

```
我在这个项目里最想讲的一条能力，不是"会跑 SFT/RM/GRPO"，而是当"业务指标没提升 / 上线不行"时，
我不会条件反射地去调 RL 参数，而是把它当成一个主诉症状，在整条链路上做差分诊断。

因为在这个项目里，"指标没动"出现过四次，一线直觉每次都指向"再调调 RL"，但没有一次能靠调 RL 超参解决：
- v6.5 的 375 步零移动，根因在评测层——训练 val 的 attack 破功 11% 根本不等于产品的 55%；
- v6.7 的 clean 提不动，根因在 RM 层——clean 轴打分跨度只有 0.037，RL 在平轴上空转；
- v6.8 的富度反而变坏，根因在数据 / 选择器层——选择器成了放大器，把独白过冲到 187%；
- v6.10 的 attack 压不动，根因在 credit 层——那条 -5 是整条回复级的，落不到破角 span。

所以我把这条链路拆成 8 个候选病因，每个都配一个比重训便宜几个数量级的离线判别实验：
分布比对、采样 sweep、分轴方差、组件消融、加数据看斜率、扫超参看响应。
关键是认清"同症状不同病灶"——比如 attack 不降可能是 RM 无方差、也可能是 credit 无定位，
我用"分轴方差是否为零"一个判别量就能把它们分开。

这让我把归因从"猜是不是 RL 的问题"，升级成"按成本从低到高，把症状逼到唯一正确的那一层"。
```

一句话：

```
把"指标没动"当主诉而不是诊断——先证症状为真，
再按成本从低到高用一串廉价判别器逐层排除，
本项目四次"指标没动"分属评测 / RM / 数据 / credit 四个不同层，没有一次能靠"调 RL 超参"解决。
```
