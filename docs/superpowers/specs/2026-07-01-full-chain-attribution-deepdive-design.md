## 1. 目标与定位

写一篇教用户/读者**"全链路差分归因能力"**的 deep dive：当**业务指标没提升 / 上线效果不行**这个症状出现时，如何在整条 RLHF 链路上，把根因判给**正确的那一层**，并说明每一层的**判别方法与实验设计**。

组织方式：**差分诊断法（Differential Diagnosis）**——锁定一个主诉症状，对每个候选病因给出"若是它会看到什么特征 + 用什么最小实验把它与相邻病因区分开"，再用项目里真实的"指标没动"事件当已确诊病例。

**与相邻 deep dive 的分工（必须在正文点明，避免重叠）：**
- 深读 5 = *前向* 门：判断"该不该起 RL"（Gate A/B/C/D/E）。
- 深读 8 = *单一透镜*：只讲 credit assignment 这一个视角。
- **深读 9 = *后向* 差分诊断**：症状已经发生（指标没动 / 上线不行），逐层排查锅在哪。credit assignment 只是差分树里的**一列/一节**，深链到深读 8，**不重推公式**。

## 2. 核心论点（贯穿全篇）

在这个项目里，"指标没动"至少出现过 4 次；一线直觉每次都指向"RL 算法 / 参数"，但真实根因 **0 次**在算法本身。**归因错层比问题本身更贵**——归因能力 = 不被表面症状骗、按成本从低到高系统性逐层排除。

### §0. 反直觉的起点：同一个症状，四个不同病灶（全篇钩子，已确认保留）

一张表：同一个表面症状（"指标没动 / 破功没降"），项目里 4 次事件根因分属 4 个不同层；一线直觉全指向"RL 算法"，真实命中 0 次。

| 事件 | 表面症状 | 一线直觉归因 | 真实根因层 |
|---|---|---|---|
| v6.5 375 步零移动 | attack 不降 | "RL 学不动=算法/参数" | 评测层（val 11%≠产品 55%） |
| v6.7 clean +0.037 | clean 提不动 | "RL 步数不够" | RM 层（clean 轴跨度 0.037 无方差） |
| v6.8 独白过冲 187% | 富度坏了 | "SFT 数据不够" | 数据/选择器层（选择器=放大器） |
| v6.10 attack 压不动 | attack 不降 | "RL 没调好" | credit 层（-5 无法定位到破角 span） |

结论句：4 次"指标没动"，一线直觉全指向 RL 算法，真实根因 0 次在算法本身 → 确立本篇论点。

每节固定模板：**症状表现 → 特征指纹（怎么和相邻层区分）→ 最小判别实验（控什么变量、看什么信号、成本）→ 项目确诊案例（真实数字）→ 常见误判**。

层序按"从便宜到贵 / 从前到后"排查：

| § | 层 | 项目确诊案例（全部为仓库既有真实数字） |
|---|---|---|
| 2 | 评测 / 度量层 | v6.5 val 11%≠产品 55%；业务↔技术代理错配；同尺重算（raw vs 去误报，如 v6.7 混合分 +0.092 vs 分轴 +0.013） |
| 3 | 数据层 | A6 任务注入/代码在 defense 池 0 覆盖；v6.8 选择器=放大器（独白进目标→过冲 187%）；判别=加数据看斜率 |
| 4 | SFT 强度层 | v6.9→v6.9c unique defense 120→2686（22×）真破功 32.4%→33.8% 斜率反转；step0 自蒸馏 78.8% in-char 良率否决"teacher 太弱"假说 |
| 5 | RM 层 | clean 跨度 0.037 vs attack 0.36（~10×）；RM v2 acc 退步根因=batch 减半+score head 保存 bug；RM v3 根因=cosine LR 步数不足；判别=分轴方差离线预检 |

### §11. 归因方法论提炼（可迁移，跨项目）

抽象通用原则：
- (a) **先证症状为真再归因**：同尺重算 + 生产/评测分布比对，排除"度量假象"。
- (b) 每层都有**比重训便宜几个数量级的离线预检**（分布比对 / 分轴方差 / 加数据看斜率 / 组件消融 / 采样扫描）。
- (c) **控制变量**：一次只动一层。
- (d) **廉价判别器**：斜率、方差、分轴、分源、同尺。
- (e) **易混病因对 + 判别关键**小表：例如"RM 无方差(§5)"与"credit 无定位(§8)"都表现为"attack 不降"，如何用"分轴方差是否为零"把两者分开；"数据覆盖缺口(§3)"与"SFT 范式到顶(§4)"都表现为"加数据看似该有效"，如何用"斜率是否反转"分开。
