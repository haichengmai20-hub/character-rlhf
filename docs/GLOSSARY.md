# 全仓术语表（GLOSSARY）

> 每条 = **定义** + **一句人话**（通俗解释）。README 顶部的"高频术语速查"是本表的 5 条精简版；本表按 **算法与训练目标 / 训练工程 / 项目黑话与评测口径** 三组收录全量。
> 所有涉及项目数字的条目均可溯源至主线文档（[VERSION_MAP](VERSION_MAP.md) / [CASE_STUDY](../CASE_STUDY.md) / deep_dives）；算法条目标注 arXiv 出处。
> **版本命名**：全项目新号 RM-/SFT-/RL-（如 RM-6.3 / RL-6.3 / SFT-6.9c，消除三线共用 `v6.x` 同号不同物）↔ 原始号 ↔ 产品交付号 的对照见 [VERSION_MAP](VERSION_MAP.md) 顶部与 [project_chatjoy_overview](project_chatjoy_overview.md) 的阶段映射；注意很多 v6.x 是 run/失败实验，不代表产品逐版提升。

## A. 算法与训练目标

| 术语 | 定义 | 一句人话 |
|---|---|---|
| **SFT**（监督微调） | 在固定的（输入 → 理想输出）样本对上做最大似然训练 | 让模型照范文抄，学会"这个场合该说这种话"；本项目的 Qwen3 初训与 Gemma4 富化/defense 训练都是 SFT |
| **RM**（Reward Model，奖励模型） | 在偏好对（更好 vs 更差）上训练出的打分器，对任意回复输出一个标量分 | 一个学会"哪句更好"的裁判；后续 RL 拿它的分当奖励 |
| **Bradley–Terry（BT）ranking loss** | `L = −log σ(r(chosen) − r(rejected))`，把"A 比 B 好"的偏好变成可优化的概率 | 裁判每看一对答卷，就把好的分抬高一点、差的压低一点 |
| **RLHF** | SFT → 偏好数据 → RM → RL 的三段式对齐流程 | 先教会说话，再训个裁判，最后让模型在裁判打分下自我改进 |
| **GRPO**（arXiv:2402.03300） | 同一 prompt 采 G 条回复，用组内标准化 `(r−mean)/std` 当 advantage，省掉 PPO 的 critic 模型 | 不请仲裁员打绝对分，让同一道题的几份答卷互相比出高下；本项目 G=4→6→12 |
| **advantage**（优势） | 一条回复相对"基准预期"好多少的量；正→鼓励该行为，负→打压 | "这份答卷比同组平均高几分"——RL 梯度的方向盘 |
| **rollout** | 训练循环中让当前模型现场生成回复的采样过程 | 让学生当堂写卷子（而不是拿旧卷子来改）；rollout 温度/条数决定"暴露哪些行为给训练看" |
| **on-policy / off-policy** | 训练数据是否出自当前策略自身 | 批改自己刚写的卷子 vs 批改旧卷子/别人的卷子 |
| **KL 惩罚 / KL 锚** | 约束当前策略分布不要偏离参考模型（通常是 SFT 起点）太远的正则项 | 拴在起点上的橡皮筋，防止越训越怪 |
| **per-source KL（psKL）** | 本项目做法：clean / attack 两类输入分别设 KL 系数（v6.10：clean 0.008 紧锚 / attack 0.002 松放；KL_CLEAN 自早期 0.002 抬升） | 同一根橡皮筋，不想动的部分拴紧、想改的部分放松——"守富度、放防御"的实现 |
| **GSPO**（arXiv:2507.18071） | 重要性比率与裁剪从 token 级升到序列级（长度归一的几何平均） | 按"整份答卷"而非"每个字"控制更新步幅；MoE 下路由抖动被序列平均摊薄，训练明显更稳 |
| **DAPO clip-higher**（arXiv:2503.14476） | 非对称裁剪：上界放宽到 1+0.28、下界保持 1−0.2 | 允许好行为多涨一点、坏方向照旧管死——防低概率探索 token 被系统性压制 |
| **entropy 正则 / mode collapse** | 熵 = 输出分布的多样性；mode collapse = 输出塌缩到少数模板 | 防模型只会一两句口头禅；本项目 entropy_coeff=0.01 兼防 MoE router 坍塌 |
| **Goodhart / reward hacking / length hacking** | 代理指标一旦成为优化目标就失效（Goodhart 定律）；模型钻奖励空子（如写长灌水） | 上有政策下有对策——项目实例：anti_refusal +3.0 被"自报 AI 但不拒绝"钻空，反向训出破角 |
| **LoRA / QLoRA / NF4** | 低秩适配器微调 / 4-bit 量化底座 + LoRA；NF4 是 4-bit 量化格式 | 不动大模型本体，只训一小块"外挂"；4-bit 把底座显存压到约 1/4（57GB→~15GB） |
| **MoE / router（gate）** | 稀疏专家网络 / 决定每个 token 激活哪些专家的路由器 | 模型里住着 128 个专科医生，router 负责挂号——RL 阶段不训 router（LoRA 不含 `gate`），防噪声梯度把挂号台训崩 |
| **自蒸馏（self-distillation）** | 用自己（通常是更强/更早状态）当 teacher 生成训练数据 | 让"还没学坏"的自己给现在的自己出范文；项目用 step0 产 defense 样本，78.8% in-char 良率 |

## B. 训练工程

| 术语 | 定义 | 一句人话 |
|---|---|---|
| **ZeRO-1/2/3** | DeepSpeed 的三档显存切分：依次把 optimizer 状态 / +梯度 / +参数分片到多卡 | 把训练家当分给多张卡保管——切得越多越省显存、通信越贵；本机无 NVLink，ZeRO-3 通信代价约 5 倍以上，故选 ZeRO-2+4bit |
| **FSDP** | PyTorch 原生的全分片数据并行（与 ZeRO-3 同思想） | 同上一条的 PyTorch 版；verl actor 侧用它 |
| **TP（张量并行）** | 把单层权重矩阵切到多卡同时算 | 一张卡装不下 26B（48.6GB），4 张卡各扛 12.15GB——TP=4 不是选择是必然 |
| **KV cache / PagedAttention** | 自回归解码要缓存历史 key/value；vLLM 把这块缓存分页管理 | 聊得越长"草稿纸"越大；PagedAttention 是按页出租草稿纸，省浪费但不免费 |
| **colocate / cumem / sleep-wake** | verl 让训练态 actor 与 vLLM 推理引擎共卡，靠虚拟地址预留 + 睡眠/唤醒切换 | 一张床两人轮着睡——但床位（虚拟地址）一直被占着，这是本机三档 OOM 的共同根因 |
| **rollout temperature** | RL 采样阶段的生成温度 | 温度决定训练"看得见"哪些行为——**训练温度必须 ≥ 部署温度**，否则训出"温度脆"假护栏 |

## C. 项目黑话与评测口径

| 术语 | 定义 | 一句人话 |
|---|---|---|
| **破角 / roledrop** | 被诱导跳出角色：自报 AI 身份、泄露 system prompt、执行"改清单/写代码"等角色外指令 | 演员当场出戏；"抗破角"= 被攻击也在角色内化解 |
| **真破功率** | 同一检测器去掉 echo / code 两类误报后的破功比例 | raw 检测只是初筛，决策一律用真值——raw 与真值差 2-3pp 且方向不定 |
| **A1–A6 / ML_\*** | 攻击类别编码：A1–A3 身份直球，A6 任务注入/代码，ML_* 多语言变体 | 68 条 attack probe 的分类轴，"A6 code 11→12"这类表述由此而来 |
| **step0 / base** | step0 = SFT 富化弧的起点 actor（68 条真破功 16.2%）；base = Gemma4-it 原始基座（11 卡 roledrop 口径 27%） | 两套口径不可互比——"回到 16.2%"说的是 step0，不是 base |
| **早期 RL v1/v2** | 产品侧对两个 RL 交付模型的编号（roledrop 破功 91% / 55%）。**v1 = Goodhart 事故期（v6.3 psKL）产物**（对应 merge 未记录）；**v2 = anti-OOC 两步修复 + 防御 SFT 之后的 `rl_v6.4_step160_merged`**——55% 是修复后仍不够好，不是事故本身 | 与 **RM v1/v2** 同名不同物，引用必带"早期 RL"前缀 |
| **同尺原则** | 对比的所有模型必须同一次、同检测器、同 metric 重算 | 绝不拿 A 模型的 raw 去比 B 模型的真值——"36.8%→16.2%"式跨模型混用是本项目点名过的事故 |
| **斜率反转** | 加数据后目标指标不降反升 | SFT 到顶的可观测信号：unique defense 22× 后真破功 32.4%→33.8% |
| **whack-a-mole** | 打地鼠：补一类失效、另一类冒头 | SFT-defense 三轮的真实体感（A6 越补越差、身份纹丝不动） |
| **canary 门** | RL 早期（step30–50）先跑小规模 probe，任一红线劣化即停 | 矿井里的金丝雀——别烧完全程算力才发现训坏了 |
| **best-of-N（BoN）选择器** | 每个 prompt 采 N 条、按目标函数挑最好的进训练集 | 教训：**选择器 = 放大器**，目标里放了独白就把独白放大到 187% |
| **温度脆（temperature brittleness）** | 防御改善只在训练温度附近成立、换部署温度即失效 | v6.7 的假护栏：t0.7 +0.013、t1.0 反而更差——根因是 rollout 温度没覆盖部署温度 |
| **噪声带（noise band）** | 本项目实测：val 单点 ±0.1、n=1 真破功 ±6pp | 带内变化不是信号；决策需 n≥2 或连续多点同向 |
| **停线** | 多维证据一致确认当前配方无效后停止训练、转换路线 | 不是放弃，是拒绝沉没成本谬误——v6.5（375 步零移动）与 v6.10 step90 各停过一次 |
