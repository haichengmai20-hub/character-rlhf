## 修改权限与事实判断分别处理

- 用户当前任务决定修改目标和范围；已确认 Canonical 是正文维护基线，不是不可质疑的事实。未经相应授权不擅自重写，但发现错误立即指出，不等待批准才表达异议。
- 判断历史发生了什么时，核对真实运行日志、产物及其对应脚本/配置。代码或配置单独不能证明运行成功；用户确认和助手总结不能替代一手证据。
- 区分 `[历史实跑]`、`[当前设计]`、`[口述口径｜待对账]`、`[面试模拟｜待真实重跑]`。可复算不等于已复现；模拟不能用于声称真实 checkpoint、线上效果或显著性。
- Canonical 与历史证据冲突时说明双方对象、时间、单位和证据强弱。若只是不同设计，分别陈述；若事实错误，明确反驳并提出修订。用户已授权修正时局部修正；未授权时保留原文并给出具体修改建议。
- 允许计算、预算和教学模拟，标注输入、假设、分母、公式、范围和用途，不为满足面试叙事编造结果。

## 按任务推进

- 解释、答疑、只读审计：读取并回答；审计按 P0/P1/P2 给证据、影响与建议，不推断正文写权限。
- 明确要求修订、新建或已批准方案：先核对对象、证据和现状，然后完成写入与验证，不重复要求“方案批准 → 聊天全文批准 → 文件批准”。用户明确要求先看全文时照办。
- 目标或重大结构/口径不清：先完成独立盘点，再澄清真正影响结果的问题。小型且可逆选择说明假设后推进。
- 局部勘误不顺带把完整正文压缩成摘要；保护无关改动和历史快照。新增导航、同步其他目录、提交或发布须属于当前授权范围。

## 写作与验证

- 业务问题 → 数据/模型方案 → 指标与失败样本 → 归因与竞争解释 → 决策。机制主线优先，版本用于映射；不预设版本越新效果越好。
- 独立文档中的陌生术语给定义和人话解释。公式说明方向、粒度、mask 和成立条件；关键数值说明统计单位、分母、切片、时间与证据身份。
- SFT/RM/RL/产品与重启编号独立；Pair、Response、Prompt、Trajectory、Token Exposure 不混计；不同协议或 score 尺度不直接画成可比趋势。
- 高风险因果、公式、数字血缘或大规模结构修订安排独立复核，主 agent 最终核验；简单格式和局部措辞不机械派 agent 或跑全量测试。
- 写后读回、查编码与受影响链接，必要时复算数字、检查公式和 Git diff。飞书导入任务再使用飞书专项校验。完成声明仅覆盖本次验证范围。
