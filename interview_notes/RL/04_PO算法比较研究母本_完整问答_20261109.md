### 完整回答 A01｜回应 Q01

<!-- ORIGINAL-BEGIN:A01 sha256=bd4ebe1a0fdd9cc3497edd78a2983156a615bd60e9e210eabf62c03a3532c029 source_line=611 -->
**GSPO 可以作为你的优先实验候选，但还不能据现有理由认定它优于 DPO、GRPO。** 你对 PPO 成本的判断基本成立；对 GSPO 的理解需要修正“GRPO 连乘误差”和“消除训推不一致”两点；排除 OPD 的理由则需要更换。

下面先核对机制，再给出可直接交给工作模型实施的实验方案。**本轮提供方案，没有运行训练或修改文件。**

**一、GRPO 与 GSPO：最关键的纠正是，GRPO 没有把整段 token ratio 连乘**

令一次回答为 $y=(y_1,\ldots,y_T)$，每个 token 的比率为：


$$
r_t(\theta)=
\frac{\pi_\theta(y_t\mid x,y_{<t})}
{\pi_{\mathrm{old}}(y_t\mid x,y_{<t})}
$$


先忽略 KL。使用 outcome reward 时，GRPO 可以让整条回答的 token 共享同一个组内优势 $A$，但在每个 token 上计算裁剪代理目标：


$$
L_{\mathrm{GRPO}}
=
-\frac1T\sum_t
\min\left(r_t A,\operatorname{clip}(r_t)A\right)
$$


**这里是各 token 项相加／平均，不是把所有 $r_t$ 连乘。** 因此，“GRPO 因 token ratio 连乘而发生误差累积”不是正确解释。log 概率对应的是求和，也不是“log 连乘”。

GSPO 则先形成：


$$
s(\theta)
=
\exp\left(\frac1T\sum_t\log r_t(\theta)\right)
=
\left(\prod_t r_t(\theta)\right)^{1/T}
$$


然后使用：


$$
L_{\mathrm{GSPO}}
=
-\min\left(sA,\operatorname{clip}(s)A\right)
$$


也就是：**以 token ratio 的几何平均形成长度归一化的序列比率，再在序列粒度应用裁剪代理目标。** 这与整条回答的 reward、advantage 粒度一致。注意 `min` 与优势符号共同决定裁剪是否生效，不是简单把所有越界比率钳住。[GSPO 原论文 §2–4](https://arxiv.org/html/2507.18071v2)

一个纯数学例子：

假设 100 个 token 的 log-ratio 都是 $0.02$。

| 对象 | 数值 |
|---|---:|
| 每个 token ratio | $e^{0.02}\approx1.0202$ |
| 未归一化的完整序列概率比 | $e^{100\times0.02}\approx7.389$ |
| GSPO 的长度归一化比率 | $e^{0.02}\approx1.0202$ |
| GRPO 使用什么 | 分别使用各位置的约 1.0202，不使用 7.389 |

这个例子解释了**为什么完整序列比率需要控制长度效应**，不能拿它证明 GRPO 自己做了连乘。

你的面试解释可以改成：

> 我们的奖励针对完整回答。GSPO 使用长度归一化的序列比率，让回答中的 token 共享序列级更新权重和裁剪条件，因此值得检验它是否比逐 token 加权的 GRPO 更稳定，尤其是在 MoE 和较长回复下。

但还要保留两个边界：

- **token 级策略梯度配 sequence reward 本身并不矛盾。** PPO、GRPO 都可以这么做，不能仅凭“粒度不同”宣布它们错误。
- GSPO 的归一化比率是用于优化的代理量，**不等于完整序列概率比的精确重要性权重**，更不意味着更新因此完全无偏。

**二、你说的两类“训推不一致”，需要拆成不同问题**

至少区分下面三种变化：

| 变化 | 例子 | 是否属于实现误差 |
|---|---|---|
| 解码分布变化 | temperature、top-p、top-k 不同 | 可能是有意设置，必须统一概率口径 |
| 同权重、同输入，跨后端差异 | vLLM 与训练后端的精度、kernel、并行或 MoE 执行差异 | 属于需要诊断的训推实现差异 |
| 参数更新后的策略变化 | $\pi_{\mathrm{old}}$ 更新成 $\pi_\theta$，专家路由也改变 | 首先是策略更新，不应统称实现误差 |

**你提出的第一个来源成立，但必须在同权重、同 token 前缀和同概率口径下比较。**

如果输入模板、token、temperature 或 padding/mask 都没对齐，测到的 logprob 差异不能直接归因 vLLM 的数值误差。

可以用三个策略帮助理解：

- $\mu$：真正生成样本的 rollout 分布；
- $\pi_{\mathrm{old}}$：训练侧固定的更新前策略；
- $\pi_\theta$：正在更新的策略。

在同一个 token 和前缀上：


$$
\log\frac{\pi_\theta}{\mu}
=
\underbrace{\log\frac{\pi_\theta}{\pi_{\mathrm{old}}}}_{\text{更新前后的策略变化}}
+
\underbrace{\log\frac{\pi_{\mathrm{old}}}{\mu}}_{\text{采样侧与训练侧的差异}}
$$


**这两个差异不是同一件事。** 如果 old logprob 在训练侧重新计算，那么更新前 $\pi_\theta=\pi_{\mathrm{old}}$ 时，优化比率可以是 1，但 rollout 分布仍可能与它们不一致。也就是说，**优化比率看起来正常，不代表训推已经一致**。[verl 三策略与 rollout correction 说明](https://verl.readthedocs.io/en/latest/algo/rollout_corr_math.html)

**你提出的 MoE 来源也有道理，但不能写成“训练和推理必然激活不同专家”。**

GSPO 论文讨论的一项关键现象，是**做过梯度更新后，新旧策略对同一回答激活的专家发生变化**。这并不只是同一权重在两个后端的差异。后者也可能发生，但需要单独测量，不能从论文现象直接推定你的实现也存在。[GSPO §5.3](https://arxiv.org/html/2507.18071v2)

因此，更准确的共同影响是：

> 后端差异会造成采样分布与训练计算不一致；MoE 路由变化可能使概率变化更剧烈。这些因素都可能影响梯度估计和更新稳定性，但不是同一种误差，也不是都通过 token ratio 连乘体现。

**GSPO 可能降低部分局部波动的影响，但不会自动修复这些差异。**

例如，对 log-ratio 中近似零均值、弱相关的扰动，取平均可能减小波动；如果所有位置都存在同方向的系统偏差，平均后偏差仍在。错误权重同步、错误模板、严重数值差异，也不会被 GSPO“平均正确”。

**三、PPO：你的成本理由成立，但应表达为优先级判断**

常见 PPO-RLHF 实现需要学习 value/critic，用于估计优势，这会增加：

- 前向、反向及优化器成本；
- 显存或模型调度压力；
- value 估计、GAE、value loss 等调试工作。

不过，**PPO 不必总是加载一份独立、同尺寸的 critic**；策略与价值模型可以共享参数。因此，不能把“PPO 必然多一个完整大模型”写成算法定义。[PPO 原论文](https://arxiv.org/pdf/1707.06347)

适合你的论证是：

> 我们已有完整回答级奖励，并计划对同一 Prompt 生成多个候选。组相对优势提供了不训练 critic 的方案，因此优先比较 GRPO/GSPO，降低实现与调试成本。PPO 是否值得增加 critic，需要由其收益和实际资源开销决定。

还有一点：**G=6 的采样也要花钱。** 不能只计算 PPO 的 critic 成本，却不计算 GRPO/GSPO 的额外候选生成成本。

**四、OPD：不能因为“不是 Agentic RL”就排除**

这里把 OPD 理解为 **On-Policy Distillation，在线策略蒸馏**。

它通常让学生自己生成回答，再让教师在**学生实际走到的前缀**上提供下一 token 的分布或 logprob。它可以减轻离线教师轨迹与学生自生成轨迹之间的 exposure bias，但不能保证所有分布偏移都消失。[GKD 原论文](https://arxiv.org/html/2306.13649)

你可以把完整回复视作一个环境侧动作，形成单步决策问题；但在生成内部：


$$
(x,y_{<t}) \rightarrow y_t \rightarrow (x,y_{\le t})
$$


仍然存在 token 前缀的连续变化。**一个回答即使只对应一次用户交互，也可能从中间开始偏离理想轨迹。** OPD 因而不只适用于长程 Agent。

“像 SFT 一样有密集信号”可以作为直觉，但机制不同。例如一种常见 PG-OPD 使用教师与学生的 token logprob 差作为蒸馏信号；它不是人工标注的逐 token 奖励，也不等同于普通 SFT 交叉熵。[Thinking Machines 的 OPD 实现](https://thinkingmachines.ai/blog/on-policy-distillation/)

对你而言，是否采用 OPD，应检查：

1. **教师在角色、语言、丰富度与防御上是否确实值得模仿。**
2. 教师能否对**学生已经生成的任意序列**进行 teacher-forced logprob 评分。仅能返回教师自己生成内容的 logprob 不够。
3. tokenizer／词表是否兼容，或是否已有可靠的跨词表方案。
4. 教师在学生错误前缀上的指导是否可靠。
5. 教师评分成本是否值得，是否会同时蒸馏进不想要的风格和拒绝习惯。

所以，合理的暂不采用理由是：

> 当前有可验证的业务偏好评分器，但尚未具备同样可靠、可访问逐 token 信号且成本合适的教师，因此优先比较基于偏好的路线。

**“outcome reward 已经足够”只能是待验证的工作假设，不能由“单轮任务”直接推出。**

---

**五、DPO：你确实可以复用 RM 的偏好数据，而且应当认真比较**

DPO 与 RM 都可以使用：

```text
同一个 Prompt
├── chosen
└── rejected
```

区别在于：

- RM 学习给回答评分；
- DPO 用偏好对直接更新 Actor；
- RM＋GSPO 先让当前 Actor 生成新候选，再用 RM 评分并更新。

因此，**现有偏好对是支持 DPO 的理由，不是排除它的理由。** 标准离线 DPO 不需要另训练显式 RM，也不需要在训练循环中持续 rollout。[DPO 原论文](https://arxiv.org/html/2305.18290)

不过，你项目中的数据复用要检查：

- chosen/rejected 是否共享相同的角色卡、历史与用户输入；
- raw history 换成 summary 后，原来的偏好方向是否仍成立；
- 数据是否主要由明显错语言、错角色的简单负例组成，还是覆盖当前 Actor 的细粒度差异；
- chosen 是否含 Teacher 风格、过长回复或不合业务的拒绝行为；
- 是否与 Dev/Test 隔离。

**支持选择 GSPO 的潜在理由**是：旧偏好对对当前策略的新错误覆盖不足，而可靠 RM 能对新生成候选持续提供有用排序。

但这不是自动成立的优势：

- RM 可能在新候选上失效，甚至被 Actor 利用；
- DPO 可能已经足够，且更便宜；
- 也存在不断刷新偏好数据的 online/iterative DPO，不能把“DPO 永远只能学习旧数据”当作定义。

你的选型应允许得出：

> 如果 DPO 在相同资源预算下达到同等或更好的业务质量，就选择 DPO；只有在线采样带来的额外收益足以抵偿成本，才选择 GSPO 路线。

---

**六、具体实验方案：分成“机制对照”和“路线选择”两层**

这样才能回答两个不同问题：

| 对照 | 要回答的问题 | 能归因到什么 |
|---|---|---|
| GRPO vs GSPO | 同一奖励、数据与采样条件下，优化方式有什么差别？ | 比率、裁剪及其相关优化行为 |
| DPO vs RM＋在线 RL | 利用现有资产，在预算内哪个方案更值得？ | 完整路线的质量、成本与工程取舍 |
| PPO／OPD 条件性加入 | critic 或 teacher 是否值得额外成本？ | 对应完整方案，不能只凭机制先宣布失败 |

以下数字都是**建议实验设置**。

**A．固定一个阶段，避免初始化混杂**

建议先在你当前较完整的第二阶段验证：

```text
Actor 起点：同一个 Targeted-SFT checkpoint
Reference：冻结的同一个 checkpoint
在线奖励：通过诊断的固定 RM-B＋固定结构规则
```

如果要解释最初 SFT-final 后的算法选择，应另用那个阶段的初始化和资产做比较，不能把第二阶段结果倒写成第一次选型已经得到的证据。

统一：

- tokenizer、模板、输入视图与截断方式；
- LoRA target、rank、可训练参数；
- response mask、EOS 处理；
- GRPO/GSPO 的优势计算、loss 聚合方式；
- KL、entropy、MoE 辅助项等共同设置；
- 同步方式、每批数据复用次数。

**先按 Family 隔离 Train/Dev/Test，再做摘要或攻击改写。**

**B．准备训练与评测数据**

| 数据 | 建议设置 |
|---|---|
| 在线 RL Prompt 池 | 800 个不同训练 Prompt：Clean 560＋Attack 240；五类 Attack 可各 48 |
| DPO 数据 | 开放与 RM 同源的**完整合格偏好池**，按预算平衡抽样 |
| 继续 SFT 对照 | 使用合格 chosen，帮助判断收益是否只需继续监督学习 |
| Dev | Clean 200 Scene＋Attack 100 Scene；固定生产候选解码协议 |
| Final-Test | 独立来源家族；配置锁定后比较入围方案与固定基线 |

**不能让 RM 已经学习三万 Pair，却只给 DPO 八百 Pair，然后声称标签条件公平。** 八百 Pair 可以用于首批检查，不能据此淘汰 DPO。

如果 RM 原数据是 raw history，而算法实验使用 summary，先完成输入转换与标签复核。来不及转换时，可以先在共同 raw 协议下诊断，但要限定结论，并在实际目标输入协议下补确认。

评测可以每 Scene 采样两次；若生产协议是确定性 greedy，重复相同运行不增加独立证据。

**C．先做一个很小的训推差异诊断**

用 32 个固定 Prompt，每题生成 6 条，共 **192 个回答**：

1. 冻结同一权重版本，不做更新。
2. 固定 token IDs、前缀、mask、精度和 logprob 定义。
3. 诊断时可使用 `temperature=1`、不做 top-p/top-k 截断，减少解码分布混杂。
4. 保存 rollout logprob，并在训练后端重算同一批 token。
5. 若能记录路由，再比较同位置、同层的专家集合；没有路由记录就不声称已定位 MoE 原因。

定义：


$$
\delta_t=
\log p_{\mathrm{train}}(y_t\mid x,y_{<t})
-
\log p_{\mathrm{rollout}}(y_t\mid x,y_{<t})
$$


至少报告：

- $\delta$ 的有符号均值；
- $|\delta|$ 的 p95/p99；
- 按回答长度、Clean/Attack 分层的差异；
- 可观测时的路由一致率。

**只看均值会漏掉正负抵消。**

然后在更新前后分别检查策略变化。不要把更新后的所有概率变化继续记为“后端误差”。

这个诊断只能确定差异是否存在，不能单独证明 GSPO 更好。

**D．主比较的批量与预算**

在线 RL 采用：

| 项目 | 设置 |
|---|---|
| 每 iteration | 32 Prompt |
| 每 Prompt 候选数 | G=6 |
| 每批回答 | 192 Responses |
| Minibatch | 按当前笔记的 verl 口径：16 Prompt，展开为 96 Responses |
| 每批优化遍数 | 1 |
| 每 iteration 更新次数 | 2 |
| 完整短试 | 25 iterations |
| 对应规模 | 800 Prompt visits、4,800 Responses、50 次参数更新 |

只有不重复抽取时，800 visits 才等于 800 个不同 Prompt。实施时核对所用 verl 版本的 minibatch 字段单位。

**至少要有多次参数更新。** 在起点 current=old、归一化和正则完全相同时，GRPO/GSPO 的初始梯度可能相同；只比较第一次更新看不出关键差别。

两层预算分别处理：

- **GRPO vs GSPO：**相同 Prompt 顺序、生成预算与更新安排；各自从当前策略生成，不能全程共用冻结旧 rollout 却仍称 on-policy。
- **DPO vs 在线 RL：**比较相同的新增资源预算。用短 profile 估计完成 25 个 GSPO iteration 的 GPU 小时，作为预算上限参考。DPO 可以更早达到目标，不必为了“花满预算”继续训练。

GPU 小时应计入 Actor、Ref、RM、Critic、Teacher 等实际占用和必要计算。另列从零构建路线的总成本，避免既有 RM 的历史投入被隐藏。

**E．超参数与快速筛选**

建议控制搜索规模，先每个主算法最多两个配置：

| 算法 | 起步探索建议 |
|---|---|
| GRPO | 两个小学习率，例如 $1e{-6}$、$3e{-6}$；使用 token 级裁剪 |
| GSPO | 同样两个学习率；使用序列级裁剪并单独校准范围 |
| DPO | 固定小学习率，例如 $1e{-6}$，先比较两个 β，例如 0.05、0.1 |

这些是起点，不是最优参数承诺。

**不能让 GRPO 与 GSPO 使用同一 clipping 数值来制造“公平”。** 原论文比较中，GSPO 使用的左右范围为 $3e{-4}/4e{-4}$，GRPO 为 $0.2/0.27$，数量级明显不同；这些值也不能直接保证适合你的场景。[GSPO §5.1](https://arxiv.org/html/2507.18071v2)

你当前 [launcher](/D:/RL及harness/character-rlhf/training/GRPO_Training_Package/framework_bridge/verl/train_grpo_lora_actor_verl.sh:186) 中，GSPO 默认范围是 `0.2/0.28`。这只证明脚本默认值，不证明实际运行配置；但选型实验应先检查其有效裁剪情况，不能直接照搬为合理基线。

DPO 的 β 与 RL 的 KL 系数也不应数值强行相同。需要使用**共同评测口径测得的策略偏移**，检查是不是某种方法只是走得更远。

建议执行顺序：

1. DPO、GRPO、GSPO 各两个配置，做相当于约 10 个 RL iteration 的筛选预算；在线方法对应约 1,920 Responses/run。
2. 根据 Dev、稳定性和成本，留下两个方案。
3. 两个入围方案各用两个训练 seed，在完整短试预算下确认。
4. 结果接近时，增加独立场景或第三个 seed；仍不明确就报告暂时不能区分。

两个 seed 只是快速重复性检查，不足以证明普遍稳定性。预算更紧时，可以先每算法一个配置预筛，但只能淘汰明显不工作的配置。

**F．PPO 和 OPD 怎样加入**

- **PPO：**先测 critic 的显存、吞吐和训练链路成本。若资源可接受，给它合理的 value 初始化／校准，再进入短试；不能让随机 critic 只学几步，就宣布 PPO 不行。资源不足时记录“本轮预算不采用”，而非“效果已被证明更差”。
- **OPD：**先确认教师业务能力、学生序列评分接口及 tokenizer 兼容性；检查教师在学生错误前缀上的指导。通过后纳入同资源预算短试，教师成本全部计入。未通过时记录具体前提缺失。

---

**七、用什么指标决定结果**

**第一层看业务效果，第二层看诊断，第三层看成本。**

| 层次 | 指标 | 用途 |
|---|---|---|
| 核心业务 | Attack 真破角率、合格角色内化解质量 | 是否解决目标问题 |
| 旧能力保留 | Clean 盲评偏好胜率、角色贴合、承接、推进、丰富度与密度 | 是否通过牺牲正常体验换防御 |
| 行为护栏 | 语言错误、格式错误、通用拒绝、重复、截断、生成失败 | 防止指标投机 |
| 更新诊断 | 共同口径 KL、熵、梯度异常、ratio 尾部、有效梯度比例 | 判断训练是否健康 |
| 奖励诊断 | 组内 reward std、零优势组比例、RM 排错样本 | 区分“算法不行”和“根本没有有效信号” |
| 成本 | 总 GPU 小时、峰值显存、生成及评分量、达到目标的成本 | 判断收益是否值得 |

这里有几条不能省略：

- **训练 reward 上升不等于业务改善。** 正式行为评测使用独立 Judge／人工复核，而不是再用训练 RM 自己验收。
- DPO loss、GRPO loss、GSPO loss 不能直接横向比较大小。
- GSPO 和 GRPO 的 clip fraction 单位与含义不同，不能直接说“谁 clip 少谁更好”。
- 按 Scene／Family 计算配对差异和置信区间；两个采样不是两道独立题。
- 100 个 Attack Scene 适合快速筛明显差异，不宜根据两三个百分点的变化就认定胜负。
- “没有改善”要先排除零优势、RM 无区分度、全部有效更新被阻断等问题。

选择规则应在看结果前写清：

| 实验结果 | 合理决策 |
|---|---|
| DPO 达到相同业务质量，成本更低 | 选 DPO |
| GSPO 相比 GRPO，在相同采样预算下业务更好，或质量相当但运行更稳定、成本更低 | 支持选择 GSPO |
| GSPO reward 更高，但独立评测不改善 | 不支持选择 GSPO，检查奖励利用 |
| GSPO 优势仅在明显训推差异存在时出现，修复差异后优势消失 | 结论限于该运行条件，不能泛化成算法普遍更强 |
| OPD 通过教师资格检查，短试效果和成本更好 | 可以改选 OPD |
| 各方法差异落在噪声范围内 | 根据成本与工程负担暂定选择，并保留不确定性 |

如果要进一步支撑“GSPO 的优势来自对训推差异更稳健”，再补一个小型 **2×2 对照**：

```text
             当前实现条件     经过验证的一致性改进
GRPO              A                  B
GSPO              C                  D
```

一次只改变一种明确措施，例如已支持的路由 replay 或 rollout correction，并记录它是否改变了实际优化语义。不能只给 GSPO 开校正、不给 GRPO 开，然后把收益归因 GSPO。

面试中的方法选择可以组织成下面这样，最后一句等实际结果填写：

> 我们先根据资源和监督信号确定候选：PPO 增加 value 学习成本，OPD 需要可靠且可评分的教师，所以核心比较从 DPO、GRPO、GSPO 开始。GRPO 与 GSPO 在相同奖励和采样条件下比较；DPO 则获得完整合格偏好数据，按同资源预算比较。最终依据独立业务评测、旧能力保留、稳定性和成本选择方案，而不是预先认定 GSPO 最好。

### 完整回答 A02｜回应 Q02

时间：2026-11-09 01:04:34。

<!-- ORIGINAL-BEGIN:A02 sha256=14aa376588f3e51541633ec4476aa471104ae8d189d1989196c07438793c7246 source_line=632 -->
**对，在第一步参数更新之前，如果 current 和 old 使用相同参数、相同计算口径，那么 $\pi_\theta/\pi_{\mathrm{old}}=1$，它的 log 就是 0。** 我上条没有把时间点讲清楚。

关键是：**每次计算 loss 都发生在本次更新之前，但未必发生在这一批数据的所有更新之前。**

例如，用 $\theta_0$ 采样一批回答，再分成两个 minibatch 更新：

| 时间点 | 当前参数 | 固定的 old 参数 | current / old |
|---|---|---|---|
| 第一次计算 loss | $\theta_0$ | $\theta_0$ | 1 |
| 第一次更新完成 | 变成 $\theta_1$ | 仍是 $\theta_0$ | — |
| 第二次计算 loss | $\theta_1$ | 仍是 $\theta_0$ | 通常不再是 1 |

第二个 minibatch 的回答仍然是旧策略 $\theta_0$ 生成的，但计算 loss 的模型已经被第一个 minibatch 更新了。因此：


$$
r_t=
\frac{\pi_{\theta_1}(y_t\mid x,y_{<t})}
{\pi_{\theta_0}(y_t\mid x,y_{<t})}
$$


**这里的“新策略”是相对采样时的旧策略而言，并不是尚未执行的下一次更新。** old logprob 在这批数据的更新期间保持固定，current logprob 则随参数重新计算。

再回到你引用的公式：


$$
\log\frac{\pi_\theta}{\mu}
=
\log\frac{\pi_\theta}{\pi_{\mathrm{old}}}
+
\log\frac{\pi_{\mathrm{old}}}{\mu}
$$


在**第一次更新前**：

- 第一项为 0：尚未发生参数更新。
- 第二项仍可能非零：$\mu$ 是实际 rollout 分布，可能与训练侧重算的 old 分布存在后端、精度或解码口径差异。
- 如果两侧分布也完全一致，那么总比率就是 1，总 log-ratio 就是 0。

还有一个边界：**如果每批新采样数据只做一次整体更新，然后立即重新采样，那么每次更新起点的 current/old 都可以是 1。** 多个 minibatch 或重复使用同一批数据，才会出现上述“已经更新过，但还在使用旧样本”的情况。

比率当前为 1 也不意味着没有梯度：分母固定，分子仍是关于 $\theta$ 的函数，模型依然能够更新。

### 完整回答 A03｜回应 Q03

时间：2026-11-09 01:05:58。

<!-- ORIGINAL-BEGIN:A03 sha256=d922a829d3fa9dd70db3553e9835f05cc59be0ea2f42d0165d60d7fe7d8d560d source_line=644 -->
**对，如果你说的 step 是一次 RL 外层迭代，那么一个 step 里可以包含多个 minibatch，参数会在处理这些 minibatch 时依次更新。**

但要区分三个层级：

| 名称 | 含义 | 是否更新参数 |
|---|---|---|
| RL step / iteration | 采样一批回答、评分，再完成这一批训练 | 内部可以更新多次 |
| Optimizer step | 完成一个训练 minibatch 的梯度计算与累积 | 更新一次 |
| Microbatch | 因显存限制，把 minibatch 再拆小 | 通常只累积梯度，累积结束才更新 |

沿用刚才的例子，一个 rollout batch 分成两个 minibatch：

```text
RL step k 开始
│
├─ 用 θ₀ 生成整批回答，固定 old logprob
│
├─ Minibatch 1
│    用 θ₀ 计算 current logprob
│    current / old = 1
│    反向传播、更新参数：θ₀ → θ₁
│
├─ Minibatch 2
│    用 θ₁ 计算 current logprob
│    old 仍来自 θ₀
│    current / old 通常不再等于 1
│    反向传播、更新参数：θ₁ → θ₂
│
└─ 同步新权重，进入下一次 rollout
```

所以，**第一个 minibatch 还没有经历本批更新；后面的 minibatch 使用的模型，已经被前面的 minibatch 更新过了。**

如果日志中的 `step` 指的是 **optimizer step**，那它通常就只表示一次参数更新。讨论训练步数时，要先说明计的是哪个层级。

**一、GRPO 与 GSPO：最关键的纠正是，GRPO 没有把整段 token ratio 连乘**
令一次回答为 \$y=(y_1,\ldots,y_T)\$，每个 token 的比率为：
\

$$
 r_t(\theta)= \frac{\pi\_\theta(y_t\mid x,y\_{\<t})} {\pi\_{\mathrm{old}}(y_t\mid x,y\_{\<t})} \
$$


先忽略 KL。使用 outcome reward 时，GRPO 可以让整条回答的 token 共享同一个组内优势 \$A\$，但在每个 token 上计算裁剪代理目标：
\

$$
 L\_{\mathrm{GRPO}} = -\frac1T\sum_t \min\left(r_t A,\operatorname{clip}(r_t)A\right) \
$$


**这里是各 token 项相加／平均，不是把所有 \$r_t\$ 连乘。** 因此，“GRPO 因 token ratio 连乘而发生误差累积”不是正确解释。log 概率对应的是求和，也不是“log 连乘”。
GSPO 则先形成：
\

$$
 s(\theta) = \exp\left(\frac1T\sum_t\log r_t(\theta)\right) = \left(\prod_t r_t(\theta)\right)^{1/T} \
$$


然后使用：
\

$$
 L\_{\mathrm{GSPO}} = -\min\left(sA,\operatorname{clip}(s)A\right) \
$$


也就是：**以 token ratio 的几何平均形成长度归一化的序列比率，再在序列粒度应用裁剪代理目标。** 这与整条回答的 reward、advantage 粒度一致。注意 `min` 与优势符号共同决定裁剪是否生效，不是简单把所有越界比率钳住。[GSPO 原论文 §2–4](https://arxiv.org/html/2507.18071v2)

### 完整回答 A04｜回应 Q04

时间：2026-11-09 01:09:01。

**真正会发生“逐步比率连乘”的，是未做长度归一化的完整序列／轨迹重要性权重。不是普通 GRPO 的逐 token 裁剪目标。**

还要纠正一个容易混淆的地方：**log-ratio 为 0.02，不一定是误差，也可能是参数更新后真实的概率变化。** 下面分别说明。

**1．完整序列的重要性权重，确实包含连乘**

设目标策略为 $\pi_\theta$，生成数据的策略为 $\mu$。对同一条回答：


$$
W(y)
=
\frac{\pi_\theta(y\mid x)}{\mu(y\mid x)}
=
\prod_{t=1}^{T}
\frac{\pi_\theta(y_t\mid x,y_{<t})}
{\mu(y_t\mid x,y_{<t})}
=
\prod_{t=1}^{T}r_t
$$


因此：


$$
\log W(y)=\sum_{t=1}^{T}\log r_t
$$


**概率比连乘，等价于 log 概率比相加。不存在这里所说的“logprob 连乘”。**

这个 $W$ 会出现在完整轨迹的重要性采样中。例如，希望用旧策略生成的回答估计新策略的期望奖励：


$$
\mathbb E_{y\sim\pi_\theta}[R(y)]
=
\mathbb E_{y\sim\mu}[W(y)R(y)]
$$


该等式要求采样分布具有足够的支持集覆盖。完整轨迹的离策略回报估计、某些离策略策略梯度方法，会用到这种权重。[verl 的轨迹级重要性采样推导](https://verl.readthedocs.io/en/latest/algo/rollout_corr_math.html)

如果某条回答的每个 token 都有 $\log r_t=0.02$，那么：


$$
W=e^{0.02T}
$$


100 个 token 时为约 7.389。**如果这些比率都算得准确，这不是计算错误，而是整条回答在两个策略下的概率确实相差这么多。**

但这种乘积可能让不同回答的权重差异很大，导致有限样本估计被少数大权重样本主导——这是**统计方差问题**，即使完全没有数值计算误差，也可能存在。

**2．如果每个 token 的 logprob 有误差，乘积又会放大这些误差**

这里才严格讨论你说的“误差累积”。

设真实的 token log-ratio 是：


$$
\ell_t=\log r_t
$$


实际算出来的是：


$$
\widehat{\ell}_t=\ell_t+\delta_t
$$


其中 $\delta_t$ 才代表后端数值差异等原因造成的计算偏差。那么：


$$
\widehat W
=
\exp\left(\sum_t\widehat{\ell}_t\right)
=
W\exp\left(\sum_t\delta_t\right)
$$


因此：


$$
\boxed{\frac{\widehat W}{W}
=
\exp\left(\sum_t\delta_t\right)}
$$


**这就是明确的误差累积链条：token log-ratio 的误差相加，再经过指数变成权重的乘法误差。**

纯示意：假设某条回答每个位置都存在同方向误差 $\delta_t=0.02$：

| 回答长度 | 计算出来的权重／真实权重 |
|---|---:|
| 100 token | $e^2\approx7.389$ 倍 |
| 1,000 token | $e^{20}\approx4.85\times10^8$ 倍 |

这是**持续同向偏差**的算例，不代表实际后端误差就是这个量级。如果误差有正有负，可能部分抵消；如果误差相互关联，也不能假定平均后自然消失。

用 log-space 计算可以避免直接连乘小概率带来的下溢，但**不能消除上述偏差或重要性权重本身的高方差**。

**3．GSPO 的长度归一化，改变的是这种长度放大效应**

GSPO 使用：


$$
s=W^{1/T}
=\exp\left(\frac1T\sum_t\ell_t\right)
$$


存在同样的计算误差时：


$$
\boxed{\frac{\widehat s}{s}
=
\exp\left(\frac1T\sum_t\delta_t\right)}
$$


如果仍假设所有 $\delta_t=0.02$，那么无论 100 还是 1,000 个 token：


$$
\frac{\widehat s}{s}=e^{0.02}\approx1.0202
$$


所以可以说：

> **相对于未归一化的序列乘积，GSPO 避免了这种同向 log-ratio 偏差随长度直接指数放大的现象。**

但是：

- 剩下的约 2% 偏差仍然存在，没有被消除。
- 取 $T$ 次方根改变了权重，所以它不再是上述期望等式里的原始 $W$，不能说仍在进行同样的精确重要性校正。
- **这个比较对象是未归一化的序列权重，不是 GRPO。** [GSPO 的比率定义与长度归一化](https://arxiv.org/html/2507.18071v2)

**4．那么 GRPO 论文讨论的“噪声累积”是什么？**

忽略 clipping、KL，并把优势 $A$ 当作固定量，单条回答的梯度形式分别是：


$$
g_{\mathrm{GRPO}}
=
\frac{A}{T}\sum_t
r_t\,\nabla_\theta\log\pi_\theta(y_t\mid x,y_{<t})
$$


$$
g_{\mathrm{GSPO}}
=
\frac{A\,s}{T}\sum_t
\nabla_\theta\log\pi_\theta(y_t\mid x,y_{<t})
$$


区别在于：

- **GRPO：**不同 token 的梯度分别乘各自的 $r_t$，裁剪是否生效也分别判断。
- **GSPO：**同一回答的 token 共享序列系数 $s$，以序列为单位判断裁剪。

GRPO 中，局部 ratio 的异常波动可能改变不同 token 梯度的相对权重；加入裁剪后，还会改变哪些位置继续提供梯度。这些扰动进入整条回答的梯度，再影响后续参数更新。**这属于加权梯度与优化过程的噪声问题，不是“把 ratio 连乘导致指数爆炸”。** GSPO 论文讨论了这一现象及其 MoE 实验，但不能仅凭 token 数变多，就数学上断言 GRPO 的噪声必然越来越大。[GSPO §3–5](https://arxiv.org/html/2507.18071v2)

你可以这样记住三个不同概念：

| 说法 | 对应的真实问题 |
|---|---|
| 完整轨迹的概率比连乘 | 序列重要性权重可能高度分散，逐 token 计算误差也可能累积 |
| GRPO 的 token ratio 波动 | 各位置的梯度权重及裁剪行为受到扰动 |
| 生成时前面答错，后面越走越偏 | 自生成前缀导致后续状态变化，属于行为轨迹上的错误传播 |

**你原先把第一种的“乘积放大机制”，用来解释第二种的 GRPO 不稳定了；需要把这两条因果链分开。**

**区别在于：一个先改变“比率怎么算”，另一个后决定“损失怎么汇总”。因为中间有 `exp` 和裁剪，两处除以长度不能互相替代。**

还有一个重要补充：**原始 GSPO 的比率归一化，会在求导时自然带来 $1/T$。因此，不能把它理解成还必须把序列 loss 再除一次长度。**

下面用两条回答贯穿解释：

```text
短回答 S： [s1] [s2]                         T = 2

长回答 L： [l1] [l2] [l3] [l4]
           [l5] [l6] [l7] [l8]              T = 8

T 只计算有效回答 token，不包括 prompt 和 padding。
```

**一、比率长度归一化：发生在“计算更新幅度”的位置**

先假设每个位置的 token 概率比都是 `1.02`：

```text
当前策略给这个 token 的概率
────────────────────────── = 1.02
旧策略给这个 token 的概率
```

如果使用未归一化的整段概率比：

```text
短回答：
1.02 × 1.02
      │
      ▼
  W_S = 1.0404


长回答：
1.02 × 1.02 × 1.02 × 1.02 × 1.02 × 1.02 × 1.02 × 1.02
                              │
                              ▼
                         W_L ≈ 1.1717
```

两条回答的**平均每 token 变化程度相同**，但长回答的整段概率比更大。

GSPO 改成先平均 log-ratio：

```text
各 token 的 log-ratio
          │
          ▼
        求和
          │
          ▼
      除以长度 T       ← 比率的长度归一化在这里
          │
          ▼
         exp
          │
          ▼
   一个序列比率 s
          │
          ▼
   与 advantage 结合
          │
          ▼
   判断裁剪分支、形成 loss
```

也就是：


$$
s=\exp\left(\frac1T\sum_t\log r_t\right)
$$


于是：

```text
短回答：
exp(2 × log(1.02) / 2) = 1.02

长回答：
exp(8 × log(1.02) / 8) = 1.02
```

**这里改变的是进入裁剪目标的那个数。**

为了看清影响，假设两条回答的优势都为正，裁剪上界取 `1.1`。这只是演示参数：

| 比率定义 | 短回答 | 长回答 |
|---|---|---|
| 未归一化整段比率 | 1.0404，未触及上界 | 1.1717，触及上界 |
| GSPO 归一化比率 | 1.02，未触及上界 | 1.02，未触及上界 |

因此，**比率归一化会改变裁剪分支和梯度行为**。它不只是把最后的 loss 数字缩小一点。

这里没有说未归一化比率算错了：长回答的完整联合概率确实变化得更多。GSPO 选择的是用**平均 token 的 log 概率变化**来构造更新权重和裁剪尺度。[GSPO 比率定义](https://arxiv.org/html/2507.18071v2)

---

**二、Loss 长度归一化：发生在“这些训练项各占多少权重”的位置**

现在暂时不讨论比率。假设每个 token 的损失已经算好，记作 $\ell_t$。

仍用长度为 2 和 8 的两条回答。为展示汇总方式，使用下面这组抽象损失数值：

```text
短回答的 token loss：
[1] [1]

长回答的 token loss：
[3] [3] [3] [3] [3] [3] [3] [3]
```

这些数值只演示聚合，不沿用上一节的 ratio 数值。

**方式 A：把整个 batch 的所有 token 放在一起平均**

```text
短回答：[1] [1]                         总和 = 2
长回答：[3] [3] [3] [3] [3] [3] [3] [3] 总和 = 24
          │
          └──────────┬─────────────
                     ▼
                总和 2 + 24
                     │
                     ▼
              除以总 token 数 10
                     │
                     ▼
               Batch loss = 2.6
```

可以改写成：


$$
L_{\mathrm{token\ mean}}
=
\frac{2}{10}\underbrace{1}_{短回答平均loss}
+
\frac{8}{10}\underbrace{3}_{长回答平均loss}
$$


所以：

```text
短回答的序列权重：20%
长回答的序列权重：80%
```

**虽然叫“平均 loss”，长回答仍然占更大权重，因为它贡献了更多 token。**

**方式 B：每条回答内部先平均，再对回答平均**

```text
短回答：[1] [1]
          │
          ▼
      (1 + 1) / 2 = 1 ──────────┐
                               │
                               ▼
                         (1 + 3) / 2 = 2
                               ▲
                               │
长回答：[3] [3] ... [3]         │
          │                    │
          ▼                    │
        24 / 8 = 3 ────────────┘
```

对应：


$$
L_{\mathrm{sequence\ mean}}
=
\frac12
\left(
\frac12\sum_{t=1}^{2}\ell_{S,t}
+
\frac18\sum_{t=1}^{8}\ell_{L,t}
\right)
$$


此时：

```text
短回答的序列权重：50%
长回答的序列权重：50%
```

**这里控制的是样本在总目标中的权重，不是在重新计算概率比。**

更细地看，每个 token 前面的汇总系数是：

| 汇总方式 | 短回答每个 token | 长回答每个 token |
|---|---:|---:|
| 全 batch token 平均 | $1/10$ | $1/10$ |
| 每条回答先平均，再平均回答 | $1/4$ | $1/16$ |

第二种方式中，长回答虽然有更多 token，但每个 token 的汇总系数更小，使两条回答都占一个等权样本的位置。

---

**三、为什么“最后把 loss 除以 T”不能代替“比率里除以 T”？**

把裁剪损失整体记作 $f(z,A)$，其中 $z$ 是比率。

两种做法分别是：


$$
\underbrace{
f\left(\exp\left(\frac{\sum_t\log r_t}{T}\right),A\right)
}_{先归一化比率}
$$


以及：


$$
\underbrace{
\frac1T f\left(\exp\left(\sum_t\log r_t\right),A\right)
}_{最后缩放loss}
$$


它们一般不相等。

```text
路径 1：比率里归一化

log-ratio 求和
    → 除以 T
    → exp
    → 判断裁剪
    → loss


路径 2：最后归一化 loss

log-ratio 求和
    → exp
    → 判断裁剪
    → loss
    → 除以 T
```

继续看刚才长回答的例子：

```text
路径 1：
先归一化 → 比率 1.02
          → 没触及 1.1 上界
          → 策略目标仍可提供梯度

路径 2：
不归一化 → 比率 1.1717
          → 正优势下选中裁剪后的常数分支
          → 此项策略梯度为 0
          → 最后除以 8，仍然为 0
```

这里说的是该策略损失项的梯度；KL 等其他项仍可能有梯度。

**最后缩放 loss，无法撤销前面已经发生的裁剪分支选择。**

---

**四、落实到 GRPO 和 GSPO：两个 $1/T$ 分别在哪里？**

标准 GRPO 的路径是：

```text
每个 token 的 ratio
          │
          ▼
每个 token 分别计算裁剪损失
          │
          ▼
得到 T 个 token loss
          │
          ▼
     求和后除以 T        ← 在损失汇总处做长度归一化
          │
          ▼
   得到这条回答的 loss
          │
          ▼
    再对各条回答平均
```

公式：


$$
L_{\mathrm{GRPO},i}
=
-\frac1{T_i}\sum_t
\min(r_{i,t}A_i,\operatorname{clip}(r_{i,t})A_i)
$$


原始 GSPO 的路径是：

```text
每个 token 的 log-ratio
          │
          ▼
     求和后除以 T        ← 在比率计算处做长度归一化
          │
          ▼
         exp
          │
          ▼
    一个序列 ratio
          │
          ▼
计算一个序列裁剪损失
          │
          ▼
    再对各条回答平均
```

公式：


$$
L_{\mathrm{GSPO},i}
=
-\min(s_iA_i,\operatorname{clip}(s_i)A_i)
$$


**GSPO 已经产生一个序列 loss 标量，原始目标不需要再把这个标量除以 $T_i$。** 两种目标及其梯度可直接对照原论文公式 2、5、10、12。[GRPO／GSPO 目标与梯度](https://arxiv.org/html/2507.18071v2)

你可能接着问：GSPO 的 loss 外面没有 $1/T$，那长回答的梯度怎么办？

因为 $1/T$ 已经在 $s_i$ 里面，求导时会出来。忽略裁剪和 KL、固定优势：


$$
\nabla L_{\mathrm{GSPO},i}
=
-A_i s_i
\underbrace{
\frac1{T_i}\sum_t\nabla\log\pi_\theta(y_{i,t})
}_{token梯度的平均}
$$


对应 GRPO：


$$
\nabla L_{\mathrm{GRPO},i}
=
-A_i
\underbrace{
\frac1{T_i}\sum_t
r_{i,t}\nabla\log\pi_\theta(y_{i,t})
}_{各token分别加权后，再平均}
$$


因此：

```text
GRPO：
每个 token 各自乘 ratio
        → token 梯度平均

GSPO：
token 梯度平均
        → 共享一个序列 ratio
```

这是忽略裁剪后的示意。两者都有长度归一化，但**权重作用方式不同**。

---

**五、实现中尤其要防止“多除了一次长度”**

GSPO 已经得到一个序列标量 $L_i$ 后：

```text
情况 1：
序列 loss L_i
    → 直接对各条回答平均
    → 原始 GSPO 的方式


情况 2：
把 L_i 复制到 T 个 token 位置
    → 对这些位置求平均
    → (T × L_i) / T = L_i
    → 与情况 1 等价


情况 3：
已经只有一个序列标量 L_i
    → 再除以 T
    → L_i / T
    → 改变了目标，额外降低长回答权重
```

情况 2 的 token 平均是在消除复制产生的重复计数；情况 3 才是真正额外加了一次长度惩罚。

另外，如果把复制后的 $L_i$ 放进**全 batch token 平均**：


$$
L=\frac{\sum_i T_iL_i}{\sum_iT_i}
$$


长回答又会获得更大的序列权重，即使其 ratio 内部已经做了长度归一化。

所以你检查实现时，要沿着这条路径看：

```text
ratio 内部有没有 /T？
          ↓
裁剪发生在哪里？
          ↓
得到的是每 token loss，还是每序列标量？
          ↓
最后按 token 平均，还是按 sequence 平均？
```

**序列等权只约束目标中的汇总权重，不保证长短回答的实际梯度范数相同。** 梯度大小仍取决于 advantage、ratio、裁剪分支，以及各 token 梯度之间是同向增强还是相互抵消。

**你补充的问题，关键在于“平均的是什么、发生在裁剪之前还是之后”。**

- **先平均 log-ratio，再 `exp`、再裁剪**：改变用于裁剪的比率，这就是 GSPO 的比率长度归一化。
- **先算各位置的裁剪 loss，再平均 token loss**：只改变损失的汇总方式，不能改变前面已经作出的裁剪判断。

先把 batch、group、sequence、token 四层摆清楚，再把两条计算路径接起来。

**1．一个 batch 的结构：问题里面有回答，回答里面有 token**

这里明确约定：

- $B$：这一批有多少个 **Prompt／问题**。
- $G$：每个问题生成多少条回答。
- $T_{b,i}$：第 $b$ 个问题的第 $i$ 条回答有多少个有效 token。

例如 $B=2,G=2$：

```text
整个 Batch：2 个问题，4 条回答
│
├── 问题 q₁                         ← 第 1 个 Group
│   │
│   ├── 回答 o₁,₁：[token][token]               T₁,₁ = 2
│   │
│   └── 回答 o₁,₂：[token][token][token][token] T₁,₂ = 4
│
└── 问题 q₂                         ← 第 2 个 Group
    │
    ├── 回答 o₂,₁：[token]                      T₂,₁ = 1
    │
    └── 回答 o₂,₂：[token][token][token]        T₂,₂ = 3
```

**Group 是“同一道题的多个回答”，不是“一条回答里面的 token”。**

你的三个平均对应：

```text
一条回答内部：平均 token         除以 T
        ↓
同一道题内部：平均 G 条回答      除以 G
        ↓
这一批问题：平均 B 道题          除以 B
```

---

**2．把你的公式补全，就能直接看到三层平均**

先把某个位置的策略损失和 KL 合在一起，记为：


$$
\ell_{b,i,t}
=
-\min\left(r_{b,i,t}\hat A_{b,i,t},
r_{b,i,t}^{\mathrm{clip}}\hat A_{b,i,t}\right)
+\beta k_{b,i,t}
$$


这里 $k_{b,i,t}$ 表示该位置的 KL 项或其估计。暂时只研究怎样汇总它，不展开其计算方式。

完整 batch loss 是：


$$
\boxed{
L=
\underbrace{\frac1B\sum_{b=1}^{B}}_{\text{平均问题}}
\underbrace{\frac1G\sum_{i=1}^{G}}_{\text{平均同题回答}}
\underbrace{\frac1{T_{b,i}}\sum_{t=1}^{T_{b,i}}}_{\text{平均回答内token}}
\ell_{b,i,t}
}
$$


你第一条公式里的最外层期望 $\mathbb E$，在有限 batch 上通常用问题采样的平均来近似。

你第二条公式只显式写了一个问题对应的 $G$ 条回答。**处理多个问题时，外面还需要问题平均，或者在代码中用等价的方式完成。**

另外，$\mathcal J$ 是要最大化的目标，$L$ 是要最小化的损失，所以策略项变负、KL 惩罚变正。

**3．用具体数字，把三个平均依次算出来**

下面方括号中是**已经算好的 token loss 数值**，不是 token 概率，也不是 reward。它们仅用于演示聚合：

```text
问题 q₁
│
├── 回答 1：[1, 1]
│             │
│             └── token 平均：(1+1)/2 = 1
│
└── 回答 2：[3, 3, 3, 3]
              │
              └── token 平均：12/4 = 3

问题 q₁ 的 loss：
    两条回答平均：(1+3)/2 = 2
```

第二道题：

```text
问题 q₂
│
├── 回答 1：[2]
│             │
│             └── token 平均：2/1 = 2
│
└── 回答 2：[4, 4, 4]
              │
              └── token 平均：12/3 = 4

问题 q₂ 的 loss：
    两条回答平均：(2+4)/2 = 3
```

最后才得到整个 batch 的 loss：

```text
q₁ loss = 2 ──┐
              ├── 问题平均：(2+3)/2 = 2.5
q₂ loss = 3 ──┘
```

合起来看：

```text
token loss       sequence loss     question/group loss     batch loss

[1,1]       ──÷2──> 1 ──┐
                        ├──÷2──> 2 ──┐
[3,3,3,3]   ──÷4──> 3 ──┘            │
                                     ├──÷2──> 2.5
[2]         ──÷1──> 2 ──┐            │
                        ├──÷2──> 3 ──┘
[4,4,4]     ──÷3──> 4 ──┘
```

**这三个平均是在形成一次 loss，不是每平均一层就更新一次参数。**

**4．每一层平均，究竟赋予了谁相同权重？**

对于上面的 $B=2,G=2$：

```text
每道题在 batch 中占：
    1/B = 1/2

每条回答在 batch 中占：
    1/(B×G) = 1/4

每个 token 的汇总系数：
    1/(B×G×T)
```

具体如下：

| 回答 | 长度 $T$ | 每个 token 的汇总系数 | 整条回答的系数合计 |
|---|---:|---:|---:|
| $o_{1,1}$ | 2 | $1/8$ | $2\times1/8=1/4$ |
| $o_{1,2}$ | 4 | $1/16$ | $4\times1/16=1/4$ |
| $o_{2,1}$ | 1 | $1/4$ | $1\times1/4=1/4$ |
| $o_{2,2}$ | 3 | $1/12$ | $3\times1/12=1/4$ |

所以，三层平均表达的是：

> **每道题等权；每道题的回答等权；一条回答内部的 token 等权。**

它**不意味着整个 batch 的所有 token 都等权**。长回答里的每个 token，汇总系数会更小。

如果把所有 token 直接混起来平均：


$$
L_{\mathrm{全局token平均}}
=
\frac{2+12+2+12}{2+4+1+3}
=
2.8
$$


它与刚才的 $2.5$ 不同，因为：

```text
三层平均：
每条回答先占一个等权位置，长短回答都是一条样本。

全局 token 平均：
每个 token 占一个等权位置，长回答贡献的位置更多。
```

以上讨论的是**目标中的汇总系数**。真实梯度大小还取决于 advantage、ratio、裁剪和梯度方向，不能据此认定每条回答的梯度范数一样。

---

**5．为什么已经有 token 平均，GSPO 还要归一化比率？**

**因为 GRPO 的 token loss 平均，并没有产生或归一化一个“整段序列比率”。**

它的路径是：

```text
GRPO

token 1：r₁ → 裁剪代理目标 → ℓ₁ ──┐
token 2：r₂ → 裁剪代理目标 → ℓ₂ ──┤
token 3：r₃ → 裁剪代理目标 → ℓ₃ ──┤
  ...                            │
token T：rT → 裁剪代理目标 → ℓT ──┘
                                 │
                                 ▼
                         (ℓ₁+...+ℓT)/T
                                 │
                                 ▼
                          一个 sequence loss
```

**GRPO 用每个 token 自己的比率作判断，最后平均各位置的损失。**

GSPO 则选择先构造一个序列比率：

```text
GSPO

log r₁ ──┐
log r₂ ──┤
log r₃ ──┤
  ...    │
log rT ──┘
         │
         ▼
   平均 log-ratio        ← /T 在这里
         │
         ▼
        exp
         │
         ▼
   一个 sequence ratio
         │
         ▼
   一个 sequence 裁剪代理目标
         │
         ▼
   一个 sequence loss
```

**既然选择了序列比率，就需要处理这个比率的长度尺度。GSPO 选择用平均 log-ratio，再取指数。** 这与“最后平均 token loss”发生在不同位置。[GRPO 与 GSPO 原始公式对照](https://arxiv.org/html/2507.18071v2)

---

**6．最后除以长度，为什么不能补救前面的裁剪？**

用一个单独的算例说明。假设：

- 短回答 2 个 token，长回答 8 个 token；
- 每个 token ratio 都是 `1.02`；
- advantage 为正；
- 演示用裁剪上界为 `1.1`，不是推荐超参数。

如果直接把 token ratio 连乘：

```text
短回答：
1.02² = 1.0404
    → 没超过 1.1

长回答：
1.02⁸ ≈ 1.1717
    → 超过 1.1
```

对正优势，长回答这项会选择裁剪后的常数分支。

现在对比：

```text
先归一化比率：

长回答的 log-ratio 求和
    → 除以 8
    → exp
    → 得到 1.02
    → 没触及裁剪上界
    → 策略项仍可提供梯度
```

```text
先使用未归一化比率，最后缩放 loss：

长回答的 log-ratio 求和
    → exp
    → 得到 1.1717
    → 正优势下选中裁剪常数分支
    → 该策略项梯度为 0
    → 最后把 loss 除以 8
    → 梯度仍为 0
```

数学上就是：


$$
f\left(
\exp\left(\frac1T\sum_t\log r_t\right),A
\right)
\neq
\frac1T f\left(
\exp\left(\sum_t\log r_t\right),A
\right)
$$


其中 $f$ 包含 `min` 和 `clip`。

**后面的平均不能改变前面的裁剪分支。** 这里的零梯度只针对该策略损失项，不包括 KL 等其他项。

而且，这个算例比较的是“归一化与未归一化的序列比率”。**GRPO 本来就没有使用上述 $1.02^8$，不能把它说成 GRPO 的问题。**

---

**7．回到完整 batch：GRPO 与 GSPO 最后分别怎样平均？**

```text
GRPO
────────────────────────────────────────────
每 token ratio
    ↓
每 token 裁剪 loss
    ↓
回答内 token 平均        /T
    ↓
同题 G 条回答平均        /G
    ↓
batch 中 B 道题平均      /B
```

```text
GSPO
────────────────────────────────────────────
每 token log-ratio
    ↓
回答内 log-ratio 平均    /T
    ↓
exp → 序列比率 → 序列裁剪 loss
    ↓
同题 G 条回答平均        /G
    ↓
batch 中 B 道题平均      /B
```

原始 GSPO 的序列策略 loss 外面**不需要再额外除一次 $T$**。

它的梯度在未裁剪分支中已经包含：


$$
\nabla L_i
=
-A_i s_i\,
\frac1{T_i}\sum_t\nabla\log\pi_\theta(y_{i,t})
$$


这个 $1/T_i$ 是比率内部的归一化经过链式求导带出来的。**“比率尺度被归一化”和“梯度中出现 token 平均”在 GSPO 中由同一处 $1/T_i$ 联系起来，不是必须做两次除法。**

若 KL 采用逐 token 计算，它仍需按定义单独汇总；这不会要求把整个序列策略 loss 再除一次长度。

---

**8．最后把两个最容易重复计算的地方分开**

**第一，loss 的组内平均，与 reward 的组内标准化不是同一件事。**

```text
同题 G 个 reward
    → 求均值、标准差
    → 得到各回答的 advantage
    → 决定哪些回答被鼓励、哪些被抑制

同题 G 个 sequence loss
    → 求平均
    → 得到这道题对总目标的贡献
```

前者构造学习信号；后者汇总训练目标。即使组内 advantage 均值为 0，不同回答的梯度方向也不同，不意味着训练梯度为 0。

**第二，固定 $G$ 时，问题平均和回答平均可以合并，但不能再重复除。**


$$
\frac1B\sum_b\frac1G\sum_i L_{b,i}
=
\frac1{BG}\sum_{b,i}L_{b,i}
$$


例如一个更新 minibatch 有 16 道题，每题 6 条回答：

```text
16 × 6 = 96 条回答

先得到 96 个 sequence loss
    → 对这 96 个数求平均
    → 已经完成了 /16 和 /6
    → 不要再额外除以 6
```

其中 $B$ 应对应**这次计算 loss 的数据集合**。如果 rollout 收集了 32 道题，却分成两个各 16 道题的 minibatch 更新，那么每次更新按自己的 minibatch 汇总；不要再把完整 rollout 的 32 当作该次平均的分母。

**第一个问题：可以切换平均方式，但通常会改变优化目标中的样本权重，不是等价改写。**

**第二个问题：你的反问成立。若使用各 token 自己的 ratio 独立裁剪，就不存在“整段 ratio 连乘后受长度影响”的问题；但这也就回到了 GRPO 一类的更新方式。GSPO 的长度归一化，是配合它选择的“共享序列比率”使用的。**

下面分别展开。

**一、算法名称，不会唯一决定 loss 怎么平均**

可以把实现拆成三个部分：

```text
PO 算法的具体实现
│
├── 优势怎么计算？
│     critic / 同题组相对奖励 / 其他估计
│
├── 更新权重和裁剪怎么计算？
│     每个 token 的 ratio / 共享序列 ratio
│
└── 最后怎样汇总 loss？
      每条回答平均 / 全局 token 平均 / 固定常数归一化
```

因此，**“使用组相对优势”并不强制必须使用某一种 loss 平均方式。**

固定每题有 $G$ 个回答，将每个位置已经算好的 loss 记为 $\ell_{b,i,t}$，两种汇总分别是：


$$
L_{\mathrm{回答平均}}
=
\frac1{BG}\sum_{b,i}
\frac1{T_{b,i}}\sum_t\ell_{b,i,t}
$$


$$
L_{\mathrm{全局token平均}}
=
\frac{\sum_{b,i,t}\ell_{b,i,t}}
{\sum_{b,i}T_{b,i}}
$$


第一种是我们前面说的三层平均；固定 $G$ 时，问题平均与组内回答平均可以合并。

```text
回答平均：

短回答的 token loss → 自己内部平均 → 一份贡献
长回答的 token loss → 自己内部平均 → 一份贡献
                                      ↓
                               两条回答等权平均


全局 token 平均：

短回答的全部 token loss ──┐
                         ├→ 全部求和 / 全部有效 token 数
长回答的全部 token loss ──┘
```

**如果所有回答等长，两者等价；长度不同时，通常不等价。**

例如短回答 2 token、长回答 8 token，记两条回答各自平均后的梯度为 $g_S,g_L$：


$$
g_{\mathrm{回答平均}}=0.5g_S+0.5g_L
$$


$$
g_{\mathrm{token平均}}=0.2g_S+0.8g_L
$$


改变的是两条回答的**相对权重**。如果梯度方向不同，最终更新方向也可能改变，不能简单调整学习率就补回来。

---

**二、什么时候采用哪种方式？**

首先由你要复现的算法定义决定；主动改方案时，再根据训练目标和实验选择。

| 方案 | 汇总方式 | 主要考虑 |
|---|---|---|
| 原始 GRPO | 每条回答内部 token 平均，再平均回答 | 每条回答在聚合层面等权 |
| Token-mean 变体 | 在指定范围内，按有效 token 总数归一化 | 避免长回答里的每个 token 因 $1/T_i$ 被额外减弱 |
| 固定常数归一化 | token 项求和，除以固定常数 | 避免归一化分母随实际生成长度变化 |

这里需要补充我前面没有强调的一点：

**“每条回答等权”不等于“没有长度偏置”，也不意味着它一定更合理。**

假设两个回答都不好，优势都为负。采用每条回答内部平均时：

```text
短的错误回答：
负向更新分摊给较少 token → 每个 token 的惩罚较强

长的错误回答：
同样的序列级信号分摊给更多 token → 每个 token 的惩罚较弱
```

DAPO 的论文正是针对长推理场景，讨论这种归约方式对长回答中有效模式学习、以及重复等不良模式惩罚的影响，采用了 token-level loss。**这并不是“奖励模型多写字”：长回答的正向学习和负向惩罚都会受到影响。** [DAPO §3.3](https://arxiv.org/html/2503.14476)

Dr. GRPO 又进一步讨论了长度归一化的偏置，采用固定常数归一化；它还修改了优势的标准差归一化，因此不能把 Dr. GRPO 理解成只换一个分母。[Dr. GRPO 原论文](https://arxiv.org/html/2503.20783)

所以实际选择可以是：

- **复现原始 GRPO：**使用原始归约方式。
- **希望研究长回答 token 被弱化的问题：**比较 token-mean。
- **希望避免实际生成长度改变归一化分母：**比较固定常数方案。
- **决定最终训练方案：**看质量、正负优势下的长度变化、重复率和稳定性，不能只根据“长文本”三个字决定。

---

**三、同一个 GRPO 框架可以切换，但要写清变体**

完全可以保持：

```text
同一个 Actor
同一套组相对优势
同一个 token ratio
同一个 clipping 机制
```

只改变：

```text
seq-mean-token-mean
          ↓
token-mean
```

这是一项合理的受控实验。但表述应当是：

> “GRPO 框架，采用 token-level loss aggregation。”

而不是：

> “和原始 GRPO 完全一样，只是公式写法不同。”

实际框架也这样做。当前 TRL 的 `GRPOTrainer` 支持 `grpo`、`dapo`、`dr_grpo` 等 loss 类型，所以**类名叫 GRPOTrainer，不代表一定采用原始 GRPO 的平均方式**；仅切换 loss 类型也不等于复现了完整 DAPO 的全部机制。[TRL 官方说明](https://huggingface.co/docs/trl/main/en/grpo_trainer)

你在网上比较公式时，还要检查 **token 平均的范围**：

```text
每道题内部，把所有回答的 token 平均
    → 再平均问题
    → 问题仍等权


整个 batch 的所有 token 一起平均
    → token 数更多的问题也占更大权重
```

这两种也不同。论文公式省略 batch 维度、框架在全局累积 batch 上归一化、或者只在单卡局部 batch 上归一化，都可能造成你看到的差别。TRL 的文档也明确区分了全局累积 batch 与局部 batch 的归一化。

---

**四、你的第二个问题成立：改成每个 token 独立 ratio，就不需要 GSPO 的序列比率归一化**

关键在于，“每个 token 单独 clip”有两种不同含义。

**做法 A：每个 token 使用自己的 $r_t$。**

```text
r₁ → 自己判断裁剪
r₂ → 自己判断裁剪
r₃ → 自己判断裁剪
...
```

此时不存在：


$$
W=\prod_t r_t
$$


所以当然不需要为这个不存在的 $W$ 做长度归一化。

**但在优势、损失聚合等其他设置相同的情况下，这就是 GRPO 式目标，而不再是 GSPO 的共享序列权重设计。**

**做法 B：先算一个序列 ratio，再复制到每个 token 上。**

```text
                 序列 ratio s
                 /    |    \
                s     s     s
                ↓     ↓     ↓
              clip  clip  clip
```

如果这些位置共享同一个 advantage，它们使用相同的 ratio，裁剪判断也相同。**虽然代码逐 token 执行，实际仍是序列级裁剪。**

如果复制的是未归一化的 $W$，长度问题照样存在；逐 token 调用 `clip()` 并不会把这个数变小。

---

**五、那为什么 GSPO 要选择共享序列比率，而不直接沿用 GRPO？**

**它试图改变的是不同 token 的更新权重与裁剪决策，而不只是处理长度。**

用两个 token 的例子看最清楚。假设同一条回答：


$$
A=+1,\qquad r_1=1.5,\qquad r_2=\frac23
$$


演示用裁剪区间为 $[0.8,1.2]$。

GRPO：

```text
token 1：ratio = 1.5
    → 正优势，触及上界
    → 该策略项进入常数分支，梯度为 0

token 2：ratio = 2/3
    → 正优势下仍使用未裁剪项
    → 继续提供梯度
```

GSPO：


$$
s=\sqrt{1.5\times\frac23}=1
$$


```text
两个 token 的 log-ratio
           ↓
         求平均
           ↓
          exp
           ↓
     共享序列 ratio = 1
           ↓
      不触及裁剪边界
           ↓
两个 token 都参与该回答的更新，
共享相同的序列加权系数
```

**这才是优化行为上的区别：**

- GRPO：每个位置分别判断，相同回答里的位置可能受到不同加权、进入不同裁剪分支。
- GSPO：用整条回答的平均 log 概率变化形成共享权重，减少更新对局部 ratio 波动的敏感性。

但它也有代价：**局部较大变化可能在平均 log-ratio 中相互抵消；整条回答触发裁剪时，也可能一起抑制一些本来可以利用的位置。** 因此不能说共享序列裁剪始终优于逐 token 裁剪。[GSPO 的梯度分析与定义](https://arxiv.org/html/2507.18071v2)

---

**六、GSPO 的归一化，是这个设计选择之后需要解决的问题**

准确的逻辑顺序是：

```text
希望同一回答共享更新权重与裁剪判断
                    ↓
选择构造序列级概率比
                    ↓
完整序列概率比包含 token ratio 连乘
                    ↓
其数值尺度明显受到长度影响
                    ↓
采用平均 log-ratio，再 exp
                    ↓
得到长度归一化的共享序列比率
                    ↓
在这个比率上进行序列级裁剪
```

**所以，长度归一化是为了让 GSPO 选择的序列比率更可控；它不是在修复一个“GRPO 本来就有的序列连乘问题”。**

另外，序列 reward 并不强迫算法必须使用序列 ratio。GRPO 的 token 级目标是一种选择，GSPO 的序列级目标是另一种选择，优劣需要在任务和训练条件下比较。

你可以这样标记具体实现，避免被算法名字带偏：

| 实现 | 比率与裁剪 | Loss 汇总 |
|---|---|---|
| 原始 GRPO 式 | 各 token 的 $r_t$，分别裁剪 | 回答内部平均，再平均回答 |
| GRPO＋token-mean | 各 token 的 $r_t$，分别裁剪 | 按指定范围的总 token 数归一化 |
| 原始 GSPO 式 | 平均 log-ratio 得到 $s_i$，序列级裁剪 | 每条回答一个策略 loss，再平均回答；不额外再除一次长度 |

### 算例 1：第一次更新前 ratio=1，与后续 minibatch 的新旧差异

条件：同一 token、完全相同的条件前缀；old 固定；先不考虑后端差异。

~~~text
采样／更新起点 θ₀：
    p_old(token | prefix) = 0.10
    p_current(token | prefix) = 0.10
    ratio = 0.10 / 0.10 = 1

处理 minibatch 1 后更新为 θ₁：
    p_old(token | prefix) 仍是 0.10
    p_current(token | prefix) 假设变为 0.12
    minibatch 2 使用的 ratio = 0.12 / 0.10 = 1.2
~~~

这是单个条件概率的教学设定。它解释 current/old，不意味着 vLLM 与训练侧一定一致。如果另有 rollout 概率 μ，则 current/old 与 old/μ 分别诊断。

ratio 当前值为 1，不表示其对参数的导数为 0：分母固定，分子仍依赖当前参数。不同 minibatch 处理的是不同样本；上图仅用同一条件概率说明参数版本变化，不能据此声称所有 token 都从 0.10 变为 0.12。

### 算例 2：一个 RL iteration 内有多少次参数更新

~~~text
32 个 Prompt
    × 每题 6 条回答
    = 192 条 Responses

一个训练 minibatch：16 Prompt × 6 = 96 Responses

192 / 96 = 2 个 minibatch
    → 每个 minibatch 累积梯度后更新一次
    → 1 个 RL iteration 内有 2 次 optimizer updates

25 iterations：
    Prompt visits = 25 × 32 = 800
    Responses     = 25 × 192 = 4,800
    Updates       = 25 × 2   = 50
~~~

条件：每批只训练一遍，不额外复用、不丢样本；配置中的 minibatch 单位按该方案为 Prompt。只有不重复抽 Prompt，800 visits 才等于 800 个唯一 Prompt。microbatch 拆分本身不会自动增加 optimizer update 次数。

### 算例 3：完整序列概率比，以及计算误差怎样累积

设真实 token log-ratio 为 ℓ_t，计算值为 ℓ_t+δ_t。

~~~text
真实完整序列权重：W     = exp(Σ ℓ_t)
计算完整序列权重：W_hat = exp(Σ (ℓ_t+δ_t))

两者相除：
    W_hat / W
    = exp(Σ (ℓ_t+δ_t) - Σ ℓ_t)
    = exp(Σ δ_t)
~~~

假设每个位置都存在相同方向的 δ_t=0.02：

| 长度 T | 误差之和 | 未归一化权重的乘法误差 |
| --- | --- | --- |
| 100 | 100×0.02=2 | exp(2)≈7.389056 倍 |
| 1,000 | 1,000×0.02=20 | exp(20)≈485,165,195.409790 倍 |

GSPO 的长度归一化量 s=exp(mean ℓ_t)，对应：

~~~text
s_hat / s = exp((Σ δ_t)/T)

100 token： exp(2/100)   = exp(0.02)≈1.020201
1000 token：exp(20/1000) = exp(0.02)≈1.020201
~~~

这展示“持续同向偏差”的长度效应；不是说实际后端一定有 0.02 的误差。真实的 log-ratio=0.02 也可能只是准确的策略变化，并非计算误差。几何平均仍保留系统偏差，不能称误差已消除；它也不再是原始的精确完整序列重要性权重。

### 算例 4：比率内部除以 T，与 loss 最后除以 T

条件：每个 token ratio=1.02；回答长度分别为 2 和 8；A=+1；演示用 clip 上界为 1.1。

~~~text
未归一化完整比率：
    短回答 W_S = 1.02² = 1.0404
    长回答 W_L = 1.02⁸ ≈ 1.171659

先归一化再 exp：
    s_S = exp(2×log(1.02)/2) = 1.02
    s_L = exp(8×log(1.02)/8) = 1.02
~~~

~~~text
路径 A：先归一化比率
    log-ratio 求和 → /8 → exp → 1.02 → 未触及 1.1 上界
    正优势的该策略项仍可产生梯度

路径 B：最后缩放 loss
    log-ratio 求和 → exp → 1.171659
    → 正优势下选中常数裁剪分支
    → 该策略项梯度为 0 → loss 再 /8 → 梯度仍为 0
~~~

这里的零梯度仅针对该策略损失项，不包含 KL。此例比较归一化／未归一化的序列比率，不能说 GRPO 本来使用 1.02⁸；标准 GRPO 使用各位置自己的 1.02。

### 算例 5：每条回答平均，与全局 token 平均

输入是已经算好的抽象 token loss，不是 reward 或概率：

~~~text
短回答 S： [1,1]                   T_S=2，和=2，平均=1
长回答 L： [3,3,3,3,3,3,3,3]       T_L=8，和=24，平均=3

先平均回答内部，再平均回答：
    L_seq = (2/2 + 24/8)/2 = (1+3)/2 = 2
    短回答整体系数 = 1/2
    长回答整体系数 = 1/2

全局 token 平均：
    L_tok = (2+24)/(2+8) = 26/10 = 2.6
          = (2/10)×1 + (8/10)×3
    短回答整体系数 = 20%
    长回答整体系数 = 80%
~~~

若先按序列平均，短回答每个 token 的汇总系数为 1/(2×2)=1/4，长回答每个 token 为 1/(2×8)=1/16。若全局 token 平均，每个 token 都是 1/10。

这些是聚合系数，不保证实际梯度范数的比例也是 20%/80%。

### 算例 6：三层平均，以及“每题 token 平均”这第三种做法

~~~text
Batch：B=2，每题 G=2

q₁
├─ o₁,₁：[1,1]        → (1+1)/2 = 1 ──┐
└─ o₁,₂：[3,3,3,3]    → 12/4    = 3 ──┴→ (1+3)/2 = 2 ──┐
                                                       ├→ (2+3)/2 = 2.5
q₂                                                     │
├─ o₂,₁：[2]          → 2/1     = 2 ──┐                │
└─ o₂,₂：[4,4,4]      → 12/3    = 4 ──┴→ (2+4)/2 = 3 ──┘
~~~

| 回答 | 长度 | 每 token 系数 1/(BGT) | 整条回答系数 |
| --- | --- | --- | --- |
| o₁,₁ | 2 | 1/8 | 2×1/8=1/4 |
| o₁,₂ | 4 | 1/16 | 4×1/16=1/4 |
| o₂,₁ | 1 | 1/4 | 1×1/4=1/4 |
| o₂,₂ | 3 | 1/12 | 3×1/12=1/4 |

同一批数，三种计算会得到不同结果：

~~~text
① 每个 sequence 内 token 平均 → 回答平均 → 问题平均
   = 2.5

② 全 batch 的 token 一起平均
   = (2+12+2+12)/(2+4+1+3)
   = 28/10 = 2.8

③ 每道题内部先做 token 平均 → 再平均问题
   q₁ = (2+12)/(2+4) = 14/6
   q₂ = (2+12)/(1+3) = 14/4
   Batch = (14/6+14/4)/2 = 35/12 ≈ 2.916667
~~~

①问题等权、题内回答等权；②全局 token 等权；③问题等权、每题内部 token 等权。因此看到公式中的“token 平均”，还要确认分母覆盖一条回答、一道题、一个局部 batch，还是全局累积 batch。

### 算例 7：独立 token ratio 裁剪，与共享序列 ratio 裁剪

条件：同一回答有两个 token，A=+1；r₁=1.5，r₂=2/3；演示 clip 区间 [0.8,1.2]。这里只看策略目标项：

~~~text
GRPO 的两个位置：
    第 1 项 min(1.5,1.2) = 1.2 → 常数分支，当前梯度为 0
    第 2 项 min(2/3,0.8) = 2/3 → 未裁剪分支，保留梯度
    目标值 = (1.2+2/3)/2 = 14/15 ≈ 0.933333
    若写成最小化的策略 loss，前面加负号

GSPO：
    s = sqrt(1.5×2/3) = 1
    min(1,1) = 1，位于裁剪区间内部
    两个 token 都通过共享的序列比率参与求导
~~~

目标值大小不能用于判断算法效果；此例仅展示不同的梯度权重和裁剪分支。s 当前等于 1 也不代表它对参数的导数为 0。局部变化可以在平均 log-ratio 中抵消，因此共享序列裁剪不逐 token 检查局部偏移。

再单独核对负优势，避免把 clip 理解成“越界就一定没有梯度”：

| A | r | r×A | clip(r)×A | min 选择 | 局部行为 |
| --- | --- | --- | --- | --- | --- |
| +1 | 1.5 | 1.5 | 1.2 | 1.2 | 常数裁剪分支 |
| +1 | 0.6 | 0.6 | 0.8 | 0.6 | 未裁剪分支 |
| -1 | 0.6 | -0.6 | -0.8 | -0.8 | 常数裁剪分支 |
| -1 | 1.5 | -1.5 | -1.2 | -1.5 | 未裁剪分支 |

这里假定 advantage 固定、比率不处在边界上，且未加入 KL 等其他梯度项。

### 算例 8：序列 loss 复制到 token，与额外再除长度

假设已经得到一个序列 loss 标量 L_i=2，长度 T=8：

~~~text
原始序列汇总：
    把这个 L_i 作为一条样本，参与序列平均

实现里复制到 token 后再平均：
    [2,2,2,2,2,2,2,2]
    → 16/8 = 2
    → 只是抵消复制带来的重复计数

只有一个标量，又额外除以长度：
    2/8 = 0.25
    → 改变原来的目标，额外降低长回答权重
~~~

若把复制后的 loss 按全 batch token 平均，则结果是 Σ_i T_i L_i / Σ_i T_i，长回答又会获得更大的序列聚合权重。

GSPO 未裁剪分支的梯度为：

$$
\nabla L_i=-A_i s_i\frac{1}{T_i}\sum_t\nabla\log\pi_\theta(y_{i,t}\mid x,y_{i,<t}).
$$

这里的 1/T_i 来自 s_i=exp(mean log-ratio) 的链式求导；不是要求再把序列策略 loss 除一次长度。假定 A_i、old 和有效长度固定；KL 另算。

### 算例 9：换汇总方式可能改变梯度方向，不只是缩放学习率

这是新增的单一标量参数 θ 的教学例子：短回答 2 token，长回答 8 token；两条回答平均损失对这个参数的梯度分别为 g_S=dL_S/dθ=+2、g_L=dL_L/dθ=-1。这里研究的整个参数空间只有一个维度，不是从多维梯度中截取的投影。

~~~text
回答等权：
    g_seq = 0.5×(+2) + 0.5×(-1) = +0.5

全局 token 平均：
    g_tok = 0.2×(+2) + 0.8×(-1) = -0.4
~~~

两种梯度方向相反。对相同正学习率做梯度下降时，参数更新方向也相反。因此，在长度不同时，切换 reduction 一般不是等价公式变形。

### 算例 10：快速实验的预算不能混用数据单位

~~~text
在线 RL：
    Clean 560 Prompt + Attack 240 Prompt = 800 Prompt
    五类 Attack 等额覆盖时：240/5 = 48 Prompt/类

短筛 10 iterations：
    10×32×6 = 1,920 Responses/run

完整短试 25 iterations：
    25×32×6 = 4,800 Responses/run
    25×(32/16) = 50 optimizer updates/run

Actor Dev：
    (Clean 200 Scene + Attack 100 Scene)×2 次采样
    = 600 Responses/checkpoint
    仍然只有 300 个 Scene
~~~

DPO 可访问同源的完整合格偏好池，不能因为在线 RL 使用 800 Prompt，就只准 DPO 看 800 Pair。GRPO/GSPO 的机制对照固定共同资产；DPO 与在线 RL 的路线比较按新增资源预算及业务质量判断。重复采样不增加独立场景数，固定 greedy 重跑也不构成新的独立样本。

## 后续算法比较的扩展模板

本节用于把母本继续扩展到其他后训练算法。新增研究填写下面各项；若只是不同实现的 reduction 变化，应单独命名，不把整个算法家族混为一谈。

| 比较轴 | 新算法需要回答什么 |
| --- | --- |
| 目标与资产 | 优化业务 reward、偏好关系还是教师分布；需要 RM、critic、teacher 或固定 pair 吗 |
| 采样分布 | 数据由谁生成；在线更新前缀还是固定离线样本；是否有策略陈旧或后端差异 |
| 优势／监督信号 | token、span、sequence 还是 trajectory 级；group 只用于优势估计还是也用于归约 |
| 有效 token 与终止口径 | response mask 怎样定义；EOS、截断回答、工具观察和 padding 是否计入长度及 loss；各分母是否使用相同的有效位置 |
| 比率 | token ratio、完整轨迹乘积还是长度归一化代理量；分子、分母与 stop-gradient 分别是什么 |
| 裁剪／门控 | 在什么量上执行；粒度是什么；正负优势各走哪个分支 |
| Loss 聚合 | 每序列平均、每题 token 平均、全局 token 平均还是固定常数；是否跨设备／累积步正确加权 |
| 正则与其他目标 | KL 的方向、采样估计和聚合；entropy、router 辅助项是否改变比较 |
| 梯度 | 在 ratio=1 时有没有梯度；长度因子在哪里；改变某处是否真的等价 |
| 成本 | actor/ref/RM/critic/teacher、生成、评分和既有资产分别怎样计入 |
| 对照与指标 | 固定什么、只改什么；业务主指标、保留护栏、更新诊断和不确定性 |
| 证据与边界 | 论文条件、实现版本、实跑结果、教学算例分别是什么；什么结果会改变选择 |

建议每次新增内容继续采用“原问题 → 原回答 → 一幅 plain 图 → 一个可复算例子 → 适用条件／反例 → 来源 → 后续修正”的顺序。存档原文不删；需要改观点时，在新增勘误中链接相应 Q/A 编号。
