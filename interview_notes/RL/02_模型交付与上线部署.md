# 02｜模型交付与上线部署：RL 之后的最后一公里

> 口径：本文为 **[当前设计]**，落地《Character-RLHF 完整完善方案_20261108》§10。历史材料：仓库 `docs/runbooks/rl_v610_step90_service_guide.md` 记载过一组真实试用服务配置（4×5090、BF16、TP4、8192 上下文），可作为候选起点，不代表唯一或最低硬件方案，也不代表产品已上线。本文所有 yaml 字段为模板，`null` 代表待填。
>
> 阅读顺序：[RL 完整流程](01_RL完整流程与关键机制演进.md)（训练与 Rollout 工程）→ 本文（训练之后，模型如何真正到用户手上）。

## 0. 这一层解决什么问题

训练跑通 ≠ 产品上线。这条链上有三个最容易混淆的概念，先拆开：

```text
训练 vLLM rollout：RL 训练中生成候选的引擎，只服务训练循环
RM 打分服务：     训练/评测中的在线 scorer，不进用户请求链路
产品推理服务：     真正给用户流式回复的服务
```

前两者跑通不证明产品已经上线。交付的最小单位不是 adapter 文件，而是：

```text
模型版本 + 输入协议 + 生成配置 + 服务配置
```

四件一起交付、一起回滚。缺任何一件，「部署后的模型」就不是一个定义完整的对象。

## 1. 算法与部署方的职责分工

| 内容 | 算法主要负责 | 后端/推理工程主要负责 | 共同确认 |
| --- | --- | --- | --- |
| 资源与选型 | 模型质量、大小、适应成本的取舍 | 硬件、成本、并发、运行栈约束 | 可接受的部署范围 |
| 模型交付 | 权重血缘、adapter、tokenizer、模板和质量报告 | 正确加载与服务接口 | 导出/服务一致性 |
| 对话输入 | 角色、历史、摘要和截断的模型语义 | 会话存储、摘要流程与请求组装 | 输入协议版本与长度预算 |
| 生成行为 | 评测并推荐解码、停止与回复长度 | 实现请求参数、流式返回 | 实际生效参数和用户体验 |
| 服务运行 | 协助判断量化等变化的质量代价 | 并行、批处理、缓存、扩缩容与稳定性 | 质量/性能验收 |
| 发布反馈 | 失败归因、模型回滚候选与训练改进 | 灰度流量、监控、回滚执行 | 停止条件和下轮问题 |

算法不必亲自配置全部生产机器，但不能只交一个 adapter 而不说明对应底座及输入方式。

## 2. 三类参数分别维护

| 类别 | 例子 | 管理方式 | 是否通常要求重训 |
| --- | --- | --- | --- |
| 训练参数 | LR、rank、KL、训练 batch、梯度累积、FSDP/ZeRO | 算法维护训练配置 | 按训练实验决定 |
| 改变回答分布的参数/输入 | temperature、top_p、停止标记、max output、摘要、角色卡、截断 | 算法与后端共同维护推理协议 | 先回归质量；分布不适应时才考虑重训 |
| 服务资源/调度参数 | GPU、TP、并发批处理、KV 分配、副本 | 部署方维护服务配置 | 通常先重测性能；必要时抽查行为一致性 |

服务参数不必在训练开始前全部定死：训练早期锁定可行范围与输入语义，部署阶段在范围内调优。vLLM 的并行、显存和调度设置存在吞吐/延迟/内存取舍，具体值依赖实际硬件与工作负载。

## 3. 最小部署结构与红线服务

```text
客户端
  → 业务后端：会话状态、角色卡、历史/摘要、输入组装
  → 推理服务：通过验收的最终 Actor
  → 流式返回与必要的产品处理
```

RM、Ref、优化器、训练器和 rollout 调度**不默认进入用户请求链路**。

若显式选择 best-of-N + RM 重排，那是另一项线上方案：新增评分服务、延迟和成本评测，与「训练期 RM」是两个部署决策，不能混讲。

## 4. 交付包与两份配置

### 4.1 模型交付包（model_delivery）

```yaml

  supported_context_and_output_budget: null

  validated_precision_and_runtime: null

  rollback_model_version: null
```

交付最少包含：可加载的完整权重或**精确底座 + adapter**、相关 tokenizer/config/template、输入输出及生成约定、已验证环境范围、回归样本与报告、版本和回滚目标。

三条血缘红线：

1. **adapter 依赖对应底座。** RL adapter 若在 Targeted-SFT 合并模型上训练，部署必须使用这个实际底座，不能挂回最初下载的 M0。多段 LoRA、合并顺序或参数重参数化按实际血缘处理，不同阶段 adapter 不能随意相加。
2. **QLoRA 的训练量化与最终服务量化分别决定。** 训练时能四位加载，不表示任意四位推理格式兼容；导出、合并、再量化后的质量需按部署形态检查。
3. **记录最终生效值，不只记录客户端传入值。** vLLM 可能读取模型的 `generation_config.json`，聊天接口依赖正确的 chat template。

## 5. Serving Parity：六步由易到难

Serving Parity 检查导出并部署后是否保持预期行为，**不要求随机生成逐字相同**。

```text
1. 身份核对
   模型、底座、adapter、tokenizer、模板、特殊 token、输入内容正确
   检查重复添加特殊 token、错误 stop/EOS

2. 三形态确定性诊断
   训练侧加载 vs 导出重载 vs 目标推理引擎
   必要时看 token/logprob 差异
   数值容差结合精度与后端，不承诺逐位一致

3. 生产解码设置下的质量回归
   SR-Dev 质量与失败率
   量化版单独和参考精度比较

4. 真实多轮流程验收
   通过实际业务后端：模型回复真正写回会话
   触发摘要生成/刷新和历史截断
   覆盖关系/承诺保持、长对话、后续轮次攻击
   冻结摘要的单轮 SR 不能代替这一步
   用户侧用预定交互脚本或固定版本模拟器
   不每轮重新注入标准 assistant 历史来掩盖累积错误
   记录用户策略、会话轨迹、摘要版本，按会话/Family 统计

5. 性能压测
   短/中/长输入输出 × 预计并发
   首字延迟、完整回复延迟、吞吐、超时、错误率
   p50/p95、压测时长、到达模式、完成请求数
   端到端计时含后端组装、摘要调用、排队与流式返回
   引擎内部耗时另列

6. 单位成本
   质量达标前提下，每个成功业务请求的资源成本
   含必要的摘要等上游调用
   跨 tokenizer 的「每千 token 成本」仅作补充
```

并发 1/4/8 只是初始探测点。**没有压测数据，不写「可支持 N 个并发用户」**；服务指南文档中的 KV 容量估算（如「79x」）不等于满足延迟要求的业务并发数。

## 6. 部署问题何时反馈回训练

| 问题 | 优先处理 | 何时调整训练 |
| --- | --- | --- |
| 吞吐低但质量正常 | 调度、并行、批处理或副本 | 资源范围确实无法满足，才考虑更小模型/蒸馏 |
| 模板、底座或停止标记错误 | 修服务加载与输入 | 不应先重训 |
| 摘要遗漏角色事实 | 修摘要与状态管理 | 格式变更后模型仍明显不适应，再补同协议监督 |
| 回复过长且硬截断破坏完整性 | 检查解码与输出预算 | 用示范、偏好或奖励改善适当简洁，而非只加长度罚分 |
| 量化质量下降 | 校准数据、量化方法、精度及运行实现 | 确有必要时比较量化感知训练或蒸馏 |
| 长上下文下角色/承接变差 | 区分截断、摘要和模型能力 | 补对应数据或重新选模型，不能仅增大 max length |

## 7. 灰度、回滚与反馈

```text
灰度：
  预先定义质量、错误率、延迟、成本边界
  小范围观察
  对话有跨轮状态 → 分组按用户/会话稳定分配
  避免同一段会话每轮切换模型造成混杂

回滚对象：
  模型版本 + 输入协议 + 有效生成配置 + 服务配置 的可用组合
  回滚后确保已有会话状态可被旧协议解释

线上失败分层：
  语言 / 角色 / 历史长度 / 攻击类型 / 生成失败 / 服务错误
  先判断服务、输入、数据、RM、规则还是优化问题
  用于修复的失败样本 → 开发/训练来源
  新的独立测试 → 仍从隔离家族构建
```

## 8. 高频追问

1. **「你们的模型怎么上线的？」** 先答三类服务之分，再答交付四件套（模型+输入协议+生成配置+服务配置），最后答 Serving Parity 六步——特别是第 4 步真实多轮流程，因为它测的是训练评测覆盖不到的「摘要刷新 + 状态累积」。
2. **「vLLM 训练时不是已经在用了吗？」** 训练 rollout 引擎与产品服务是两个部署决策；前者只为训练循环服务，跑通不等于产品上线。
3. **「量化会不会掉质量？」** 训练量化（QLoRA 的 4-bit base）与服务量化是两件事；合并导出后按部署形态单独检查，量化版单独与参考精度比较（Parity 第 3 步）。
4. **「出问题先重训吗？」** 按第 6 节表格路由；模板/底座/停止标记错误修服务，摘要缺事实修摘要，只有分布性不适应才回到训练。
5. **「回滚回什么？」** 回滚的是四件套组合，不只是权重；旧会话状态要能被旧输入协议解释。
